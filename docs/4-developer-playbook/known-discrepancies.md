# ความต่างระหว่างเอกสารเดิมกับโค้ดจริง

เอกสารเดิมกับโค้ดเดินคนละจังหวะ บทนี้รวมจุดที่ยังไม่ตรงกันพร้อมหลักฐานให้ตรวจซ้ำ
ไม่ต้องเถียงจากความจำ เปิดไฟล์ตามบรรทัดที่อ้างแล้วดูเองได้เลย

- 🔍 ทุกข้อมีหลักฐานเป็น `file:line`
- ⚖️ กฎไม่เปลี่ยนเพราะตัวเลขเปลี่ยน
- 🧪 วัดซ้ำได้ด้วยคำสั่งท้ายบท

ตัวเลขทั้งหมดในบทนี้วัดจาก commit `2f73c42` เมื่อ 27 ตุลาคม 2569

## ใครใช้บทนี้

- นักพัฒนาที่ทำตามคำสั่งใน `CLAUDE.md` หรือ `docs/rules/*` แล้วไม่สำเร็จ
- ผู้ตรวจโค้ดที่ต้องตัดสินว่างานหนึ่งฝ่าฝืนกฎจริงหรือฝ่าฝืนเพียงตัวเลขที่ล้าสมัย
- ผู้ดูแลเอกสารที่ต้องการเปิด PR แก้ต้นทางโดยมีหลักฐานครบ

## ก่อนเริ่ม

- 📌 **เปิด repository ที่ commit ปัจจุบัน** เพราะบรรทัดที่อ้างอาจเลื่อนถ้ามีการแก้ไฟล์
- 📊 **เรียงความน่าเชื่อถือแบบนี้** — โค้ดที่รันอยู่และการทดสอบที่ผ่าน มาก่อนกฎเชิงพฤติกรรมใน `docs/system_prompt.md` และ `docs/rules/*` ส่วนตัวเลข รายการไฟล์ และตัวอย่างคำสั่งในเอกสารมาทีหลัง
- 🛠️ **เตรียม `grep` และ `python3`** ไว้รันคำสั่งวัดในหัวข้อ "วิธีวัดซ้ำ"

### 1) พอร์ตฐานข้อมูลทดสอบ

`CLAUDE.md` เขียนว่าฐานข้อมูลทดสอบอยู่พอร์ต `5433` ทั้งในหัวข้อคำสั่งและในคำอธิบาย
แต่ `docker-compose.test.yml:11` เปิด `"5435:5432"` พร้อมคอมเมนต์ว่า `5433` ถูกโปรเจกต์อื่นใช้
สาเหตุถูกบันทึกไว้แล้วใน `docs/skills.md:117-118` ซึ่งอธิบายว่าพอร์ตเดิมชนกับ `classroom_test_postgres`

ผลกระทบจำกัดอยู่ที่การต่อจากเครื่อง host ด้วยเครื่องมืออย่าง `psql` หรือ GUI
ส่วนคำสั่งรันเทสต์ใน container ไม่ได้ใช้พอร์ตนี้ เพราะ container คุยกันผ่านชื่อ service
ถ้าทำตามเอกสารเดิมจะต่อไม่ติด แต่ไม่ได้แปลว่าเทสต์เสีย

วิธีปฏิบัติคือใช้ `localhost:5435` และฐานข้อมูล `test_piri_db`
อย่าแก้ compose ให้กลับไปใช้ `5433` เพราะจะชนกับโปรเจกต์อื่นบนเครื่องเดียวกัน

### 2) ชื่อฐานข้อมูลทดสอบ

`CLAUDE.md:26` เรียกฐานข้อมูลว่า `test_db` แต่ `test_db` เป็น **ชื่อ service** ใน compose

## วิธีวัดซ้ำ

รันจาก root ของ repository ตัวเลขในคอมเมนต์คือผลที่วัดเมื่อ 27 ตุลาคม 2569
ใช้คำสั่งเป็นหลัก ไม่ใช่ตัวเลข เพราะตัวเลขจะเปลี่ยนเมื่อมีคนเพิ่มไฟล์

```bash
# จำนวนไฟล์ที่ใช้ FOR UPDATE
grep -rl "FOR UPDATE" backend/services/*.py | sort   # 10 ไฟล์

# จำนวนไฟล์ Vue และการใช้ style
find frontend/src -name "*.vue" | wc -l                          # 72
find frontend/src -name "*.vue" -exec grep -l "<style" {} + | wc -l   # 17
find frontend/src -name "*.vue" -exec grep -l ":style=" {} + | wc -l  # 9

# พอร์ตและชื่อฐานข้อมูลทดสอบ
grep -n "5435\|POSTGRES_DB\|DATABASE_URL" docker-compose.test.yml

# ไฟล์เทสต์ที่มีคำว่า issue
ls backend/tests | grep issue
```

การนับ endpoint ต้องอ่าน decorator ที่อาจขึ้นบรรทัดใหม่ จึงใช้สคริปต์สั้น ๆ แทน `grep` บรรทัดเดียว

```bash
python3 - <<'PY'
import pathlib, re

total = with_model = 0
for path in pathlib.Path("backend/routers").glob("*.py"):
    lines = path.read_text(encoding="utf-8").splitlines()
    for index, line in enumerate(lines):
        if not re.match(r"\s*@\w+\.(get|post|put|patch|delete)\(", line):
            continue
        total += 1
        depth = line.count("(") - line.count(")")
        block, cursor = line, index
        while depth > 0:
            cursor += 1
            block += lines[cursor]
            depth += lines[cursor].count("(") - lines[cursor].count(")")
        with_model += "response_model" in block
print(f"{with_model}/{total}")
PY
```

ผลที่ควรได้คือ `108/111`
ถ้าได้ตัวเลขอื่น ให้ตรวจว่ามี endpoint ใหม่ที่ยังไม่ประกาศ `response_model`
หรือมี decorator ที่เขียนคนละรูปแบบก่อนสรุปว่าเอกสารผิด

## ระบบทำอะไรเบื้องหลัง

ความต่างชนิดนี้เกิดจากกลไกปกติของ repository ไม่ใช่ความผิดของใครคนหนึ่ง

- 🔢 ตัวเลขในเอกสารผูกกับวันที่วัด ไม่ได้ผูกกับ commit จึงเลื่อนออกจากกันเมื่อโค้ดเดินหน้า
- 🗂️ migration เพิ่มตารางและคอลัมน์ทุกครั้ง แต่บทสรุปจำนวนตารางไม่ถูกแก้ตามในรอบเดียวกัน
- 🧱 การแยกไฟล์ service และ view ทำให้รายการยาวขึ้นโดยไม่มีใครแก้รายการในเอกสาร
- 📋 เอกสารกฎถูกคัดลอกระหว่างชั้น เช่นรายการไฟล์และจำนวน endpoint จึงมีตัวเลขซ้ำหลายที่ และเลื่อนไม่พร้อมกัน
- 🤖 repository ไม่มี CI ตรวจว่าเอกสารตรงกับโค้ด คำสั่งใน `CLAUDE.md` จึงไม่ถูกทดสอบอัตโนมัติ
- ⚠️ `CLAUDE.md` ถูกโหลดโดย agent ทุก session คำสั่งที่ผิดจึงมีผลกับงานจริงทันที มากกว่าหน้าคู่มือที่คนเปิดอ่านเป็นครั้งคราว

ด้วยเหตุนี้บทนี้จึงเลือกบันทึกหลักฐานแทนการเขียนตัวเลขลอย ๆ
และบทว่าด้วยมาตรฐานการเขียนโค้ดได้เพิ่มข้อปฏิบัติว่าไม่ควรระบุจำนวนนับโดยไม่มีวันที่วัด

## ข้อจำกัดและข้อควรระวัง

- บทนี้ไม่แก้ `CLAUDE.md` และ `docs/rules/*` เพราะเป็นกฎที่ทีมยึดและมีผลกับ agent ทุก session การแก้ต้องแยก PR พร้อมหลักฐาน และต้องอัปเดต `docs/scope.md` ด้วย
- ตัวเลขทุกตัวมีวันที่ การนำไปใช้ข้ามเดือนโดยไม่วัดซ้ำอาจได้ข้อสรุปผิด
- `grep` นับเฉพาะรูปแบบที่ตรง ถ้ามีการเขียน decorator หลายบรรทัดหรือใช้ตัวแปรช่วย ต้องใช้ตัวแยกจริง ไม่ใช่การนับบรรทัด
- กฎบางข้อเป็นค่าเริ่มต้น ไม่ใช่ด่านตรวจ การฝ่าฝืนจึงไม่ใช่บั๊กโดยอัตโนมัติ ต้องอ่านเหตุผลในไฟล์ต้นทางก่อนตัดสิน
- "แก้แล้ว" ใน `docs/scope.md` ครอบเฉพาะรายการที่ปิดในรอบนั้น ไม่ได้แปลว่าทั้งไฟล์ไม่มีข้อผิดพลาดอื่น

::: warning อย่าแก้โค้ดให้ตรงกับเอกสารเก่า
เช่นอย่าตั้งพอร์ตทดสอบกลับเป็น `5433` ให้แก้เอกสารแทน
โค้ดที่รันอยู่คือความจริง เอกสารที่ล้าสมัยคือสิ่งที่ต้องตามให้ทัน
:::

## ติดปัญหาตรงไหน? ดูวิธีแก้ตรงนี้เลย

**Q: ทำตาม `CLAUDE.md` แล้วต่อ PostgreSQL พอร์ต 5433 ไม่ได้?**

👉 **วิธีแก้:** ให้ใช้ `5435` ตาม `docker-compose.test.yml:11` พอร์ตเดิมชนกับโปรเจกต์อื่นและถูกบันทึกไว้ใน `docs/skills.md:117` คำสั่งรันเทสต์ใน container ไม่ได้ใช้พอร์ตนี้ จึงไม่ต้องแก้ compose

**Q: รัน `/app/tests/test_issue.py` แล้วขึ้นว่าไม่พบไฟล์?**

👉 **วิธีแก้:** ไม่มีไฟล์ชื่อนี้ ให้ใช้ `/app/tests/test_issues.py` หรือรัน `ls backend/tests | grep issue` เพื่อเลือกไฟล์ที่ต้องการ exit code 4 ในกรณีนี้หมายถึงหาไฟล์ไม่พบ ไม่ใช่เทสต์ล้ม

**Q: `grep` เจอ `FOR UPDATE` 10 ไฟล์ แต่เอกสารบอก 7 ต้องแก้โค้ดไหม?**

👉 **วิธีแก้:** ไม่ต้อง เอกสารตกหล่นสามไฟล์ กฎจริงคือต้องล็อกใน transaction เดียวกันและมีเงื่อนไขสถานะใน `WHERE` ให้ยึดกฎและวัดรายการใหม่ แล้วแจ้งแก้เอกสารใน PR แยก

**Q: endpoint ที่ไม่มี `response_model` มีสามตัว ผิดกฎหรือไม่?**

👉 **วิธีแก้:** ไม่ผิด เพราะเป็นข้อยกเว้นที่ระบุไว้แล้ว คือดาวน์โหลด template, SSE และ 204 ตรวจว่ามีคอมเมนต์กำกับว่าทำไมไม่มี และอย่าเพิ่มข้อยกเว้นที่สี่โดยไม่เขียนเหตุผล

**Q: `import { avatarChar } from '@/utils/avatar'` แล้วคอมไพล์ไม่ผ่าน?**

👉 **วิธีแก้:** ฟังก์ชันใน `utils/avatar` ชื่อ `avatarCharOf` ส่วน `avatarChar` เป็น computed ใน `useIdentity` ถ้าต้องการค่าที่คำนวณแล้วให้ใช้จาก composable และถ้าต้องการฟังก์ชันช่วยคำนวณเองให้ import `avatarCharOf`

**Q: ตัวเลขในคู่มือเล่มนี้เชื่อได้แค่ไหน?**

👉 **วิธีแก้:** เชื่อได้ในระดับวันที่ที่ระบุไว้ที่ต้นบท กฎและขั้นตอนนิ่งกว่าตัวเลข ถ้าจะใช้ตัวเลขเป็นเกณฑ์ตัดสิน ให้วัดซ้ำด้วยคำสั่งในหัวข้อ "วิธีวัดซ้ำ"

**Q: `docs/scope.md` บอกว่าแก้แล้ว แต่ `CLAUDE.md` ยังผิด?**

👉 **วิธีแก้:** `scope.md` เก็บทะเบียนเฉพาะรายการที่ปิดในรอบนั้น รายการในบทนี้คือส่วนที่ยังเปิดอยู่ จึงไม่ขัดกัน แต่ต้องอ่านทั้งสองที่ประกอบ ถ้าแก้ต้นทางแล้ว ให้ย้ายแถวจากบทนี้ไปที่ทะเบียนใน `scope.md`

**Q: รันชุดทดสอบนานกว่าที่เอกสารบอกมาก ผิดปกติไหม?**

👉 **วิธีแก้:** ไม่ผิดปกติ เอกสารประเมินต่ำกว่าเวลาจริงบนเครื่องนี้ ให้ตั้ง timeout ยาวพอและรันเบื้องหลัง แล้วอ่าน output ทั้งไฟล์ อย่าสรุปว่าเทสต์ค้างจากผลบางส่วนที่เห็นระหว่างรัน

**Q: ควรแก้ `CLAUDE.md` และ `docs/rules/*` ทันทีหรือไม่?**

👉 **วิธีแก้:** รอบนี้ไม่ควร เพราะไฟล์เหล่านี้ถูกโหลดเป็นกฎทุก session และมีผลกับงานที่กำลังทำอยู่ ให้เปิด PR แยกที่มีหลักฐานครบ แก้ทีละรายการ และอัปเดต `docs/scope.md` ใน PR เดียวกัน ถ้าต้องเร่งเพราะคำสั่งทำให้งานล้ม ให้แก้เฉพาะคำสั่งที่ผิดจริง เช่นพอร์ตและ path ก่อน
