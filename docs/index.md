# คู่มือระบบ PIRIvoice

PIRIvoice เป็นระบบรับแจ้งเรื่อง ความคิดเห็น และปัญหาของนักเรียน โรงเรียนพิริยาลัยจังหวัดแพร่
เรื่องที่แจ้งจะไหลตามลำดับชั้น ตั้งแต่หัวหน้าห้องและรองฝ่าย ไปยังประธานระดับ จนถึงสภานักเรียน
ระบบมีบอร์ดสาธารณะ กิจกรรม การลงทะเบียนและเช็คอินด้วยคิวอาร์ ประกาศโรงเรียน และการแจ้งเตือน
ทั้งในแอปและบนอุปกรณ์

คู่มือชุดนี้อธิบายการใช้งานตามบทบาทและอธิบายพฤติกรรมจริงของระบบ ไม่ใช่เพียงรายการปุ่ม
ทุกบทมีขั้นตอน ข้อจำกัด สิ่งที่ระบบทำเบื้องหลัง และภาคแก้ไขปัญหา

> **สถานะเอกสาร:** ตรวจเทียบกับโค้ดบนสาขา `main` ณ วันที่ 27 ตุลาคม 2026
> หากระบบถูกแก้ไขหลังวันที่นี้ ให้ยึดพฤติกรรมของโค้ดเป็นหลัก

## คำที่ต้องเข้าใจก่อนอ่าน

รายการเต็มอยู่ที่ [glossary.md](glossary.md) ต่อไปนี้เป็นคำที่พบมากที่สุด

| คำ | ความหมาย |
|---|---|
| **เรื่อง** | รายการที่นักเรียนแจ้งเข้ามา ระบบเก็บในตาราง `issues` |
| **บอร์ด** | กระดานสาธารณะ 3 ชนิด คือ โหวต พูดคุย และข้อเสนอแนะ |
| **เรื่องของฉัน** | เรื่องที่ผู้ใช้แจ้งเอง |
| **เรื่องที่รับผิดชอบ** | เรื่องที่ผู้ใช้เป็นผู้รับผิดชอบในระดับของตน |
| **ปีการศึกษา** | ปีที่สมาชิกผูกอยู่ เช่น 2569 หนึ่งปีมีหนึ่งปีการศึกษา |
| **ภาคเรียน** | ช่วงวันที่ของสถิติ หนึ่งปีมีสองภาคเรียน |
| **คู่มือการทำงาน** | หนังสืออิเล็กทรอนิกส์ 6 เล่มของสภานักเรียน |

สถานะเรื่องใช้คำเดียวกันทั้งระบบ

| รหัส | ป้ายสั้น | ความหมาย |
|---|---|---|
| `pending` | รอรับ | ยังไม่มีผู้รับ |
| `in_progress` | กำลังทำ | มีผู้รับและกำลังดำเนินการ |
| `escalated` | ส่งต่อ | ส่งขึ้นระดับสูงกว่า |
| `resolved` | เสร็จแล้ว | ปิดงานเรียบร้อย |
| `cancelled` | ยกเลิก | ผู้แจ้งยกเลิก |
| `rejected` | ปฏิเสธ | ผู้ดูแลไม่รับเรื่อง |

## สัญลักษณ์ในคู่มือ

- `คำในกล่อง` คือชื่อฟิลด์ รหัสสถานะ หรือค่าใน API
- **ตัวหนา** คือป้ายบนหน้าจอที่ต้องกดหรือมองหา
- ภาพที่ N ที่แสดงได้คือภาพจริงจาก staging ส่วนกล่อง **ภาพที่ N** ที่ยังไม่มีภาพ คือภาพที่รอแคปพร้อมเหตุผลและวิธีแคปเอง
- แผนผัง Mermaid ใช้อธิบายลำดับสถานะหรือความสัมพันธ์ของข้อมูล

## แก้ไขปัญหาและคำถามที่พบบ่อย

**ถาม: ไม่รู้ว่าตัวเองควรเริ่มอ่านเล่มไหน**
ตอบ: เริ่มจากงานที่ต้องทำ ไม่ใช่ตำแหน่ง
ถ้าต้องแจ้งเรื่องหรือติดตามสถานะ อ่านเล่ม 1 ถ้าต้องรับเรื่องหรือดูแลกิจกรรม อ่านเล่ม 2
ถ้าต้องแก้สิทธิ์ ตั้งปีการศึกษา หรือตรวจย้อนหลัง อ่านเล่ม 3 ถ้าต้องแก้โค้ดหรือ deploy อ่านเล่ม 4

**ถาม: ทำตามขั้นตอนในคู่มือแล้วไม่เห็นเมนูที่ระบุ**
ตอบ: เมนูถูกกรองตามสิทธิ์และแถวสมาชิกในปีการศึกษาปัจจุบัน
ให้เปิด **เพิ่มเติม** แล้วเทียบกับบทในเล่มที่ตรงกับตำแหน่งของคุณ ถ้ายังไม่เห็น ให้ติดต่อผู้ดูแลระบบเพื่อตรวจสิทธิ์

**ถาม: คู่มือบอกว่ามีฟีเจอร์หนึ่ง แต่ในระบบไม่มี**
ตอบ: คู่มือชุดนี้ตรวจกับโค้ด ณ วันที่ระบุไว้บนหัวหน้า
ถ้าระบบถูกแก้ไขภายหลัง ให้ยึดพฤติกรรมจริงของระบบ และแจ้งผู้พัฒนาว่าหัวข้อใดคลาดเคลื่อน

**ถาม: พบข้อความผิดพลาดบนหน้าจอ ต้องแจ้งใคร**
ตอบ: จดข้อความทั้งประโยค เวลาที่เกิด และสิ่งที่ทำก่อนเกิด แล้วแจ้งผู้ดูแลระบบ
ข้อความส่วนใหญ่มาจาก backend และใช้ค้นใน **บันทึกการใช้งาน** ได้โดยตรง

**ถาม: เอกสารเดิมกับคู่มือชุดนี้เขียนไม่ตรงกัน**
ตอบ: เอกสารเดิมยังใช้เป็นกฎวิศวกรรม ส่วนคู่มือชุดนี้อธิบายพฤติกรรมที่โค้ดทำจริง
รายการที่ขัดกันถูกสรุปไว้ที่ [known-discrepancies.md](4-developer-playbook/known-discrepancies.md) พร้อมหลักฐานในโค้ด

**ถาม: จะพิมพ์คู่มือหรือแชร์ให้คนอื่นได้ไหม**
ตอบ: ได้ ทุกไฟล์เป็น Markdown ธรรมดา
ก่อนเผยแพร่ภาพหน้าจอ ให้ตรวจว่าภาพที่แคปเองไม่มีชื่อหรือรหัสนักเรียนจริงติดอยู่
