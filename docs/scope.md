# 📐 Scope & Out of Scope (เวอร์ชันนี้)

> ⚠️ **เอกสารนี้สำคัญมาก** — ใช้เป็นกรอบป้องกันการขอเพิ่มฟีเจอร์จนพ้นขอบเขต (Scope Creep) ของเวอร์ชันปีนี้
> เมื่อครูขอเพิ่มฟีเจอร์ใหม่ ให้เปิดไฟล์นี้ดูเสมอ แล้วถามกลับว่า "อยู่ใน Scope ไหม" ก่อนรับงาน

**Deadline:** ก่อน 15 สิงหาคม (นำเสนอผลงาน + ใช้งานจริงช่วงปีการศึกษา)

---

## ✅ In Scope (ทำในเวอร์ชันนี้)

### 1. ระบบรับความคิดเห็นและปัญหา (Core)
- นักเรียน/ผู้ใช้งานทั่วไป กรอกแบบฟอร์มแจ้งปัญหา/ความคิดเห็น (ประเภท, รายละเอียด, ห้อง, ระดับ, ภาพ/หลักฐานเพิ่มเติมถ้าจำเป็น)
- ผู้รับเรื่อง มองเห็นรายการปัญหา และดำเนินการ
- **ผู้แจ้ง** เห็นสถานะการดำเนินงานปัจจุบันของเรื่องที่แจ้ง

### 2. Pyramid Escalation (การไต่ระดับงาน)
- เรื่องพุ่งเข้าหา **หัวหน้าห้อง + รอง 4 ฝ่าย** ก่อน
- หากเกินความสามารถ → ส่งต่อ (Escalate) ไป **ประธานระดับ**
- หากเกินอีก → ส่งต่อไป **สภานักเรียน / ประธานสภา**
- **แต่ละระดับมองเห็นต่างกัน** — มองลงมาเป็นขั้นแบบสามเหลี่ยมพีระมิด (ระดับสูงเห็นของระดับล่าง, ระดับล่างเห็นเฉพาะของตัวเอง)

### 3. Countdown (การนับถอยหลังงาน)
- เมื่องานถึงมือหัวหน้าห้อง/ผู้รับ ต้องกำหนด **เวลาที่ใช้แก้ปัญหา (กี่วัน)**
- มีการนับถอยหลัง; หากไม่ทันภายในเวลาที่กำหนด → ส่งต่อไประดับบน

### 4. Dashboard & รายงาน
- สถิติว่าข้อมูล/หมวดหมู่ไหนถูกแจ้งเยอะสุด
- จำนวนการเข้าใช้งาน
- รายงานผลต่างๆ สำหรับนำเสนอ

### 5. ขั้นตอนการดำเนินงาน (Status / Timeline)
- สำหรับผู้รับเรื่อง มีขั้นตอนที่สามารถเพิ่มได้ (เรื่องถึงขั้นตอนไหนแล้วตอนนี้)
- ระบบบันทึก timeline/สถานะแต่ละขั้น

### 6. การเพิ่มนักเรียนด้วยไฟล์ Excel
- นำเข้าไฟล์ Excel ที่มี: รหัสนักเรียน, ห้องเรียน, เลขที่, ชื่อ, นามสกุล, ตำแหน่งในห้องเรียน

### 7. การเข้าสู่ระบบ (Auth)
- **Login: รหัสนักเรียน / รหัสผ่าน** (ตามที่ครูเลือก)
- RBAC แยกบทบาท: นักเรียน / หัวหน้าห้อง+รอง / ประธานระดับ / สภานักเรียน / Admin

### 8. โครงสร้างข้อมูลปัญหา (Topic & Category) — ตามที่ครูกำหนด
- **หัวข้อหลัก (Topic):** `living` แจ้งสภาพความเป็นอยู่ / `problem` แจ้งปัญหา / `suggestion` ข้อเสนอแนะ
- **หมวดหมู่ย่อย (Category):** `academic` วิชาการ / `discipline` วินัย / `activity` กิจกรรม / `reception` ปฏิคม / `sanitation` สุขาภิบาล / `other` อื่นๆ
- ผู้แจ้งเลือกหัวข้อหลักก่อน แล้วกดเลือกหมวดหมู่ย่อยอีกที

### 9. รอง 4 ฝ่าย (Class Committee)
- **รองวิชาการ (vice_academic), รองวินัย (vice_discipline), รองกิจกรรม (vice_activity), รองปฏิคม (vice_reception)** — ตามที่ครูกำหนด

### 10. การตั้งค่าการแจ้งเตือน (Notification Preferences)
- ผู้ใช้ **ปิด/เปิดการแจ้งเตือนรายกลุ่ม** ได้ 4 กลุ่ม: เรื่องของฉัน / เรื่องที่ฉันรับผิดชอบ / กระดาน PIRI / รายงาน
- ปิดแล้ว **เงียบทั้งในแอพและ push** — กลุ่มที่ปิดจะไม่ถูกส่ง push ด้วย (gate อยู่ที่ `notify*` ก่อน insert
  ⇒ ใช้ค่าเดียวกันคุมทั้งสองทางโดยอัตโนมัติ ไม่ต้องตั้งซ้ำที่สอง)
- ค่าเริ่มต้น = **เปิดทุกกลุ่ม** — ผู้ใช้ที่ไม่เคยเข้าไปตั้งค่าไม่ต้องทำอะไร

### 11. สถิติส่วนตัว
- นักเรียนเห็นสถิติของตัวเอง: เรื่องที่แจ้ง / แก้ไขแล้ว / กำลังดำเนินการ / โหวต / ความคิดเห็น (แยกกระดานกับเรื่อง)
- แสดงทั้งในหน้าโปรไฟล์และหน้าแรก

### 12. การจัดการภาคเรียน (Academic Term)
- สภาตั้งภาคเรียนได้ (ชื่อ + วันเริ่ม + วันสิ้นสุด) และเลือกว่า **ภาคใดเป็นภาคปัจจุบัน**
- สถิติส่วนตัวนับเฉพาะภาคปัจจุบัน · ถ้ายังไม่ได้ตั้งภาค → นับทั้งหมด และระบุให้ชัดว่า "สถิติทั้งหมด"
- สิทธิ์ที่ใช้: `MANAGE_SETTINGS` (ไม่มี permission ใหม่)

### 13. หน้าแรกแบบรวมศูนย์
- หน้าแรกดึงข้อมูลชุดเดียว: ประกาศโรงเรียน / สรุปเรื่องของฉัน / **รอฉันตอบ** / **โหวตที่ยังไม่ได้โหวต** / สถิติส่วนตัว
- "รอฉันตอบ" = เรื่องที่ผู้ใช้เป็นผู้รับผิดชอบคนปัจจุบันและยังไม่ปิด — ต่างจาก "เรื่องที่ฉันรับ" ที่กว้างกว่า

### 14. Demo/Seed Data
- **ปีนี้จะใช้จริงเพียงช่วงสั้นๆ** — สำหรับการนำเสนอ เตรียม **ข้อมูลตัวอย่าง (Seed Data)** ให้ดูสวยงาม
- ต้องการข้อมูล "ใครแจ้งอะไร" สำหรับรายงานนำเสนอ

### 15. PWA (ติดตั้งลงหน้าจอ)
- ผู้ใช้ **ติดตั้ง PIRIvoice ลงหน้าจอมือถือ** จากเบราว์เซอร์ได้ (manifest + service worker)
- เปิดตอนไม่มีเน็ตแล้วเห็น **app shell** ไม่ใช่จอขาว
- มีแบนเนอร์ชวนติดตั้งที่ปิดได้และจำการปิดไว้ · แจ้งเมื่อมีเวอร์ชันใหม่
- ⚠️ service worker cache **เฉพาะ app shell** — **ห้าม cache `/api/*` เด็ดขาด** เพราะ cache เป็น per-origin
  ไม่ใช่ per-session; เครื่องที่ใช้ร่วมกันจะเห็นข้อมูลของผู้ใช้คนก่อน
  (นี่คือเหตุผลที่ **offline cache เต็มรูปแบบยังไม่อยู่ใน Scope** — เป็นแผนรอบถัดไป A7)

### 16. การแจ้งเตือนแบบ Push (Web Push)
- ผู้ใช้กด **"เปิดการแจ้งเตือนบนเครื่องนี้"** ครั้งเดียว → ตั้งแต่นั้นมีเรื่องใหม่/กระทู้ใหม่
  **notification เด้งขึ้นหน้าจอมือถือแม้ปิดแอปอยู่** (Web Push ผ่าน VAPID + service worker)
- **in-app ยังทำงานเหมือนเดิมเป๊ะ** — push เป็นช่องทาง *เพิ่ม* ไม่ใช่แทนที่ · ผู้ใช้ที่ไม่เปิดก็ยังเห็น badge ตามเดิม
- **ปิดกลุ่มใน §10 = เงียบทั้ง in-app และ push** (ค่าเดียวกันคุมสองทาง)
- เป็น **per-เครื่อง** ไม่ใช่ per-บัญชี — เครื่องเดียวใช้หลายคนได้ (มือถือโรงเรียน) ⇒ สวิตช์คุม "อุปกรณ์นี้"
  ส่วนจำนวนที่แสดงคือทุกอุปกรณ์ของบัญชี · **logging-in ใหม่บนเครื่องเดิม = ย้ายปลายทาง push มาที่ผู้ใช้ใหม่**
- **iOS/iPadOS ต้องติดตั้งลงหน้าจอก่อน** (Safari บนแท็บธรรมดาไม่มี `PushManager`) ⇒ UI ต้องบอกให้ติดตั้งก่อน
  ไม่ใช่โชว์ปุ่มที่กดแล้วเงียบ · **Firefox/Chrome desktop + Android ใช้ได้ทันทีโดยไม่ต้องติดตั้ง**
- ⚠️ **ต้องมี HTTPS** — clone ที่ยังเสิร์ฟ HTTP จะไม่ทำงานเลยโดยไม่มี error ให้เห็น
- ⚠️ **โหมดพักงาน:** ถ้า `VAPID_PUBLIC_KEY` ว่าง เซิร์ฟเวอร์จะ**ซ่อนการ์ดทั้งใบ** และไม่ส่ง push เลย
  (in-app ยังทำงาน) — เป็นสวิตช์ปิดฉุกเฉินที่ไม่ต้อง deploy โค้ด

## ❌ Out of Scope (ไม่ทำในเวอร์ชันนี้)

- Discord Bot — ไม่มีในระบบนี้ (โปรเจคเก่ามี แต่ PIRIvoice **ไม่รวม**)
- การเชื่อมต่อ OAuth กับ Discord/Google (ยังไม่มี)
- ระบบการเงิน/บัญชี (finance) — ไม่เกี่ยวข้อง
- ระบบตารางเรียน/ตารางสอน (schedule)
- ระบบงาน/การบ้าน (tasks/daily notes)
- **Mobile App แบบเนทีฟ** (ขึ้น App Store / Play Store) — ⚠️ **ไม่รวม PWA**
  → **PWA (ติดตั้งลงหน้าจอจากเบราว์เซอร์) อยู่ใน Scope** ตาม §15 เพราะเป็นเว็บตัวเดิม ไม่ใช่แอพใหม่
- Multi-language (ภาษาไทยอย่างเดียว)
- ระบบแชทระหว่างผู้แจ้ง-ผู้รับ
- การแจ้งเตือนผ่าน Line/Discord/Email

## 📝 หมายเหตุการตัดสินใจ
- ถ้าครูขอฟีเจอร์ที่อยู่ใน ❌ Out of Scope ให้ตอบกลับว่าอยู่ในขอบเขตเวอร์ชันไหน และเสนอเป็น "ไว้เวอร์ชันหน้า" หรือให้ประเมินผลกระทบก่อนรับ
- **แก้ล่าสุด 28 ก.ย. 2026 (รอบ 2):** เพิ่ม §16 Push — **ย้าย "Real-time push notification" ออกจาก
  Out of Scope** เพราะได้ทำจริงแล้ว · เงื่อนไขที่เคยเขียนว่า "ต้องรอ PWA (§15) ให้เสร็จก่อน" **ครบแล้ว**
  ⇒ ข้อความเดิมที่ค้างในหัวข้อ Out of Scope ถูกลบ ไม่ใช่ปล่อยไว้ให้ขัดกันเอง
- **แก้ 28 ก.ย. 2026 (รอบ 1):** เพิ่ม §10–13 และ §15 (ตั้งค่าการแจ้งเตือน / สถิติส่วนตัว / ภาคเรียน / หน้าแรก /
  PWA) · แยก **"Mobile App เนทีฟ" ออกจาก "PWA"** ให้ชัด เพราะของเดิมบรรทัดเดียวห้ามทั้งคู่ ทำให้เข้าใจผิดว่า
  ทำ PWA ไม่ได้ · แก้เลขหัวข้อซ้ำ (เดิมมี "8" สองที่)

### ⚠️ หนี้เอกสารที่ยังไม่แก้ (รู้ไว้ อย่าเพิ่งเชื่อ)
- **§8 ข้างบนไม่ตรงกับสคีมาจริง** — เอกสารบอกหัวข้อหลักคือ `living` / `problem` / `suggestion`
  และหมวดย่อยมี `sanitation` แต่ฐานข้อมูลจริง (`backend/core/init_db.py`) ใช้คอลัมน์ `main_category`
  ค่า `suggestion` / `wellbeing` / `report` เท่านั้น และ **ไม่มีคอลัมน์ `topic` เลย**
  → ต้องคุยกับครูก่อนว่าจะเอาระบบไหน แล้วค่อยแก้ทั้งเอกสารและโค้ดพร้อมกัน
- `docs/rules/backend.md` และ `docs/rules/testing.md` ยังมีกฎที่ตกค้างจากโปรเจคเก่า
  (Discord header, "Discord 999 = Admin", finance row-locking, ORM) ซึ่ง **ไม่จริง** กับ PIRIvoice
  ที่เป็น asyncpg raw SQL ล้วน
