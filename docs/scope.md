# 📐 Scope & Out of Scope (เวอร์ชันนี้)

> ⚠️ **เอกสารนี้สำคัญมาก** — ใช้เป็นกรอบป้องกันการขอเพิ่มฟีเจอร์จนพ้นขอบเขต (Scope Creep) ของเวอร์ชันปีนี้
> เมื่อครูขอเพิ่มฟีเจอร์ใหม่ ให้เปิดไฟล์นี้ดูเสมอ แล้วถามกลับว่า "อยู่ใน Scope ไหม" ก่อนรับงาน

**Deadline:** ก่อน 15 สิงหาคม (นำเสนอผลงาน + ใช้งานจริงช่วงปีการศึกษา)

---

## ✅ In Scope (ทำในเวอร์ชันนี้)

### 1. ระบบรับความคิดเห็นและปัญหา (Core)
- นักเรียน/ผู้ใช้งานทั่วไป กรอกแบบฟอร์มแจ้งปัญหา/ความคิดเห็น (ประเภท, รายละเอียด, ห้อง, ระดับ, ภาพ/หลักฐานเพิ่มเติมถ้าจำเป็น)
- ผู้รับเรื่อง มองเห็นรายการปัญหา และดำเนินการ
- **ผู้แจ้ง** เห็นสถานะการดำเนินงานปัจจุบันของเรื่องที่แจ้ง

### 2. Pyramid Escalation (การไต่ระดับงาน)
- เรื่องพุ่งเข้าหา **หัวหน้าห้อง + รอง 4 ฝ่าย** ก่อน
- หากเกินความสามารถ → ส่งต่อ (Escalate) ไป **ประธานระดับ**
- หากเกินอีก → ส่งต่อไป **สภานักเรียน / ประธานสภา**
- **แต่ละระดับมองเห็นต่างกัน** — มองลงมาเป็นขั้นแบบสามเหลี่ยมพีระมิด (ระดับสูงเห็นของระดับล่าง, ระดับล่างเห็นเฉพาะของตัวเอง)

### 3. Countdown (การนับถอยหลังงาน)
- เมื่องานถึงมือหัวหน้าห้อง/ผู้รับ ต้องกำหนด **เวลาที่ใช้แก้ปัญหา (กี่วัน)**
- มีการนับถอยหลัง; หากไม่ทันภายในเวลาที่กำหนด → ส่งต่อไประดับบน

### 4. Dashboard & รายงาน
- สถิติว่าข้อมูล/หมวดหมู่ไหนถูกแจ้งเยอะสุด
- จำนวนการเข้าใช้งาน
- รายงานผลต่างๆ สำหรับนำเสนอ

### 5. ขั้นตอนการดำเนินงาน (Status / Timeline)
- สำหรับผู้รับเรื่อง มีขั้นตอนที่สามารถเพิ่มได้ (เรื่องถึงขั้นตอนไหนแล้วตอนนี้)
- ระบบบันทึก timeline/สถานะแต่ละขั้น

### 6. การเพิ่มนักเรียนด้วยไฟล์ Excel
- นำเข้าไฟล์ Excel ที่มี: รหัสนักเรียน, ห้องเรียน, เลขที่, ชื่อ, นามสกุล, ตำแหน่งในห้องเรียน

### 7. การเข้าสู่ระบบ (Auth)
- **Login: รหัสนักเรียน / รหัสผ่าน** (ตามที่ครูเลือก)
- RBAC แยกบทบาท: นักเรียน / หัวหน้าห้อง+รอง / ประธานระดับ / สภานักเรียน / Admin

### 8. โครงสร้างข้อมูลปัญหา (หมวดหลัก & หมวดย่อย)
- **หมวดหลัก (`main_category`)** มี 3 หมวด: `suggestion` เสนอความคิดเห็น / `wellbeing` สุขภาวะทางกายและใจ / `report` แจ้งเหตุ
- **หมวดย่อย (`category`)** เป็นของหมวดหลักเสมอ — ตรึงความสอดคล้องไว้ที่ `backend/config/categories.json`

  | หมวดหลัก | หมวดย่อย |
  |---|---|
  | `suggestion` | `academic` วิชาการ · `reception` ปฏิคม · `activity` กิจกรรม · `discipline` วินัย · `democracy` ประชาธิปไตย |
  | `wellbeing` | `physical_health` สุขภาวะทางกาย · `mental_health` สุขภาวะทางใจ |
  | `report` | `complaint` ร้องทุกข์ · `grievance` ร้องเรียน |

- ผู้แจ้งเลือกหมวดหลักก่อน แล้วเลือกหมวดย่อยอีกที · ระบบ **ปฏิเสธ** หมวดย่อยที่ไม่ใช่ของหมวดหลักนั้น (`core.categories.is_valid_category`)
- 🔁 **ค่าที่ตั้งไว้ตอนแรก (`living` / `problem` / `sanitation` / `other`) ถูกแทนที่แล้ว** — ดูหมายเหตุการตัดสินใจด้านล่าง

### 9. รอง 4 ฝ่าย (Class Committee)
- **รองวิชาการ (vice_academic), รองวินัย (vice_discipline), รองกิจกรรม (vice_activity), รองปฏิคม (vice_reception)** — ตามที่ครูกำหนด

### 10. การตั้งค่าการแจ้งเตือน (Notification Preferences)
- ผู้ใช้ **ปิด/เปิดการแจ้งเตือนรายกลุ่ม** ได้ **5 กลุ่ม**: เรื่องของฉัน / **เรื่องที่รับผิดชอบ** / บอร์ด / จัดการรายงาน / กิจกรรม
  > ⚠️ คำว่า "เรื่องที่รับ" ถูกห้ามใช้ — ดู `docs/glossary.md` (ใช้ **"เรื่องที่รับผิดชอบ"** เท่านั้น)
  > ⚠️ **แก้ 2026-09-30 (R3.3)** — เอกสารนี้เคยเขียน "4 กลุ่ม" และ **ขาด "กิจกรรม" (`event`)**
  > ซึ่งโค้ดรองรับมาตั้งแต่ต้น · **โค้ดถูก เอกสารตามไม่ทัน** ⇒ แก้ที่เอกสาร ไม่ใช่ที่โค้ด
  > (แหล่งความจริง: `backend/services/notification_service.py::PREFERENCE_GROUPS` และ
  > `frontend/src/types/notification.ts::PREFERENCE_GROUP_VALUES` — ทั้งคู่มี 5 ค่าเท่ากัน)
- 🔴 **`announcement` (ประกาศฉุกเฉิน) ไม่อยู่ในกลุ่มที่ปิดได้ — และห้ามเพิ่ม**
  ประกาศฉุกเฉินที่ผู้ใช้ปิดได้ = ประกาศที่ล้มเหลว (น้ำท่วม/ไฟดับ/งดเรียน ต้องถึงทุกคน)
  ⇒ ฝั่ง UI จึงแสดงเป็น **แถวอ่านอย่างเดียวที่บอกว่า "ปิดไม่ได้" พร้อมเหตุผล** ไม่ใช่ซ่อนเงียบ ๆ
  (เดิมกลุ่มนี้ไม่ปรากฏในหน้าตั้งค่าเลย ⇒ ผู้ใช้ที่ปิดทุกกลุ่มแล้วยังเห็นประกาศเด้งต้องเดาเองว่าทำไม)
  ⚠️ `GROUP_TYPES` มี 6 ค่า (รวม `announcement`) แต่ `PREFERENCE_GROUPS` มี 5 — **อย่าสลับกันใช้**
- ปิดแล้ว **เงียบทั้งในแอพและ push** — กลุ่มที่ปิดจะไม่ถูกส่ง push ด้วย (gate อยู่ที่ `notify*` ก่อน insert
  ⇒ ใช้ค่าเดียวกันคุมทั้งสองทางโดยอัตโนมัติ ไม่ต้องตั้งซ้ำที่สอง)
- ค่าเริ่มต้น = **เปิดทุกกลุ่ม** — ผู้ใช้ที่ไม่เคยเข้าไปตั้งค่าไม่ต้องทำอะไร
- หน้าจอที่ใช้ตั้งค่า = **`/app/settings`** (แยกจาก `/app/profile` ซึ่งเป็นหน้า "ฉันเป็นใคร" — R3.3)

### 11. สถิติส่วนตัว
- นักเรียนเห็นสถิติของตัวเอง: เรื่องที่แจ้ง / แก้ไขแล้ว / กำลังดำเนินการ / โหวต / ความคิดเห็น (แยกกระดานกับเรื่อง)
- แสดงทั้งในหน้าโปรไฟล์และหน้าแรก

### 12. การจัดการภาคเรียน (Academic Term)
- สภาตั้งภาคเรียนได้ (ชื่อ + วันเริ่ม + วันสิ้นสุด) และเลือกว่า **ภาคใดเป็นภาคปัจจุบัน**
- สถิติส่วนตัวนับเฉพาะภาคปัจจุบัน · ถ้ายังไม่ได้ตั้งภาค → นับทั้งหมด และระบุให้ชัดว่า "สถิติทั้งหมด"
- สิทธิ์ที่ใช้: `MANAGE_SETTINGS` (ไม่มี permission ใหม่)

### 13. หน้าแรกแบบรวมศูนย์
- หน้าแรกดึงข้อมูลชุดเดียว: ประกาศโรงเรียน / สรุปเรื่องของฉัน / **รอฉันตอบ** / **โหวตที่ยังไม่ได้โหวต** / สถิติส่วนตัว
- "รอฉันตอบ" = เรื่องที่ผู้ใช้เป็นผู้รับผิดชอบคนปัจจุบันและยังไม่ปิด — ต่างจาก "เรื่องที่ฉันรับ" ที่กว้างกว่า
- **เมนูลัดไประบบอื่นของโรงเรียน** (เพิ่ม 1 ต.ค. 2026): การ์ดลิงก์ 2 ปลายทาง — *เว็บโรงเรียน*
  (`sites.google.com/piriyalai.ac.th/piriyalai/home`) และ *ระบบดูแลช่วยเหลือนักเรียน*
  (`ess.sesa37.go.th` ซึ่งต้องอยู่ **ลำดับแรก** เพราะเด็กเข้าเป็นอันดับ 1 และระบบอื่นอ้างอิงจากระบบนี้)
  - ⚠️ **ข้อมูลนิ่ง ไม่ได้มาจาก API ชุดข้างบน** ⇒ การ์ดนี้ต้องขึ้นเสมอ **แม้ `/api/home/summary` ล่ม**
    (ปัญหาของระบบเราต้องไม่ตัดทางออกไปหาระบบอื่นของโรงเรียน)
  - อยู่ **ใต้ประกาศโรงเรียน** และ **เปิดในแท็บเดิม** — ไม่มี `target="_blank"` ตามที่เจ้าของระบบกำหนด
    (ตอนติดตั้งเป็น PWA การเปิดแท็บใหม่จะหลุดออกจากแอป) ⇒ มีเทสต์ล็อกทั้งลำดับ ทั้ง URL และการไม่มี `_blank`
    · ที่มา/รูปแบบ: `frontend/src/constants/schoolSystems.ts` + `components/SchoolSystemsCard.vue`
- **ยุบบล็อกที่ว่างให้เหลือแถวเดียว** (เพิ่ม 2 ต.ค. 2026): บล็อกที่ *ว่างเป็นปกติ* — **รอฉันตอบ ·
  สรุปเรื่องของฉัน · สถิติของฉัน · คิวจัดการรายงาน** — เมื่อยืนยันได้ว่า "ว่างจริง" (โหลดเสร็จ +
  ไม่มี error + จำนวน 0) จะเหลือ **แถวเดียว ~44dp** ที่ยังบอกว่า *ตรวจแล้ว ไม่มีอะไรค้าง*
  แทนที่การ์ดเต็ม (หัวการ์ด + empty state ≈ 250–300dp ต่อบล็อก)
  - **ยุบ ≠ ซ่อน** — บล็อกที่ซ่อนคือ *ของที่ต้องทำ* (โหวต/กิจกรรม/ประกาศ ที่หายไปเมื่อว่างอยู่แล้ว)
    ส่วนบล็อกที่ยุบคือ *ของของฉัน* ซึ่ง "เคลียร์แล้ว" เป็น**ข้อมูล**ที่ผู้ใช้อยากรู้
  - ⚠️ **ทางออกต้องไม่หาย**: "แจ้งเรื่อง" (คำเชิญเดียวในแอปสำหรับคนที่ยังไม่เคยแจ้ง) และ
    "คิวทั้งหมด" ย้ายจากปุ่มกลางการ์ด/หัวการ์ด มาเป็นลิงก์ท้ายแถว — ยังกดได้ใน 1 แตะเท่าเดิม
  - ⚠️ **"รอฉันตอบ" ยุบได้เฉพาะเมื่อทั้งสองสัญญาณเป็นศูนย์** — ยอด *รอฉันตอบ*
    (`current_assignee_id = ฉัน`) กับ *ยังไม่อ่าน* (`issue_received`) เป็นคนละชุดกัน ⇒ ถ้ายุบทั้งที่ยังมี
    ของยังไม่อ่าน ป้าย badge ที่หัวการ์ดจะหายไปพร้อมสิ่งเดียวที่บอกว่ามีของใหม่
  - ⚠️ **"สถิติของฉัน" ยุบเฉพาะที่หน้าแรก** — `Profile.vue` ใช้การ์ดตัวเดียวกันและต้องคงกล่อง
    "ยังไม่มีสถิติในช่วงนี้" เต็มรูปแบบ (ผู้ใช้ *จงใจ* เข้าไปดูสถิติ ⇒ ความว่างคือคำตอบที่ต้องการ)
    และข้อความของแถวผูกกับ **ภาคเรียน** ("ในช่วงนี้") เพราะ `total_reported` นับตามภาค
    ขณะที่ `my_issues.total_issues` นับตลอดชีพ ⇒ ใช้คำเดียวกันจะขัดกันเองต่อหน้าต่อตา
  - **แดชบอร์ด** ไม่ได้ยุบแต่ **ซ่อนเมื่อไม่มีข้อมูล** — ของเดิม `v-if` ไม่มีสาขาสุดท้าย ทำให้ขึ้น
    *หัวการ์ดลอยที่มีปุ่มแต่เนื้อในว่างเปล่า* ซึ่งอ่านเป็น "โหลดค้าง"
  - เงื่อนไขทั้งหมดเป็นฟังก์ชันบริสุทธิ์ใน `frontend/src/types/home.ts` (ตารางความจริง + เทสต์)
    ไม่เขียนเป็น `v-if` ในเทมเพลต — เหตุผล: *ว่าง / พัง / ยังโหลดไม่เสร็จ* ให้ผลเหมือนกันถ้าเช็คแค่
    `length === 0` และ `?? []` จะกลืน "พัง" ให้กลายเป็น "ว่าง" อย่างเงียบ ๆ
  - ผลที่วัดได้ (Playwright 360dp, CSS + ฟอนต์จริง): 4 บล็อกรวม **1,125dp → 260dp** (ประหยัด 865dp
    ≈ จาก 1.8 จอเหลือ 0.4 จอ) · หลักฐาน: `~/reports/empty-collapse-2026-10-02/`
  - ✅ **ยืนยันบน staging จริง** (2 ต.ค. 2026 · หลัง deploy `8c60b5d` · บัญชี e2e ที่ seed ไว้):
    `e2eadm` ยุบครบทั้ง 4 บล็อก — การ์ด **54 / 54 / 46 / 46 dp** ตรงกับที่วัดจากหน้าเทียบ ·
    `e2ecou` ยุบ 3 บล็อก แต่ "รอฉันตอบ" ยังเป็นการ์ดเต็มเพราะมีของค้างจริง ·
    `e2estu` ไม่ยุบเลย (มีเรื่องของตัวเอง 1 เรื่อง) ⇒ ครอบครบสามสภาพ: *ยุบหมด / ผสม / ไม่ยุบ*
    · console error 0 · ลิงก์ทางออกยังถึงปลายทางจริง (`คิวทั้งหมด` → `/app/issues/received`,
    `แจ้งเรื่อง` → `/app/issues/new`) · ภาพ `~/reports/empty-collapse-2026-10-02/staging-home-*.png`

### 14. Demo/Seed Data
- **ปีนี้จะใช้จริงเพียงช่วงสั้นๆ** — สำหรับการนำเสนอ เตรียม **ข้อมูลตัวอย่าง (Seed Data)** ให้ดูสวยงาม
- ต้องการข้อมูล "ใครแจ้งอะไร" สำหรับรายงานนำเสนอ

### 15. PWA (ติดตั้งลงหน้าจอ)
- ผู้ใช้ **ติดตั้ง PIRIvoice ลงหน้าจอมือถือ** จากเบราว์เซอร์ได้ (manifest + service worker)
- เปิดตอนไม่มีเน็ตแล้วเห็น **app shell** ไม่ใช่จอขาว
- มีแบนเนอร์ชวนติดตั้งที่ปิดได้และจำการปิดไว้ · แจ้งเมื่อมีเวอร์ชันใหม่
- ⚠️ service worker cache **เฉพาะ app shell** — **ห้าม cache `/api/*` เด็ดขาด** เพราะ cache เป็น per-origin
  ไม่ใช่ per-session; เครื่องที่ใช้ร่วมกันจะเห็นข้อมูลของผู้ใช้คนก่อน
  (นี่คือเหตุผลที่ **offline cache เต็มรูปแบบยังไม่อยู่ใน Scope** — เป็นแผนรอบถัดไป A7)

### 16. การแจ้งเตือนแบบ Push (Web Push)
- ผู้ใช้กด **"เปิดการแจ้งเตือนบนเครื่องนี้"** ครั้งเดียว → ตั้งแต่นั้นมีเรื่องใหม่/กระทู้ใหม่
  **notification เด้งขึ้นหน้าจอมือถือแม้ปิดแอปอยู่** (Web Push ผ่าน VAPID + service worker)
- **in-app ยังทำงานเหมือนเดิมเป๊ะ** — push เป็นช่องทาง *เพิ่ม* ไม่ใช่แทนที่ · ผู้ใช้ที่ไม่เปิดก็ยังเห็น badge ตามเดิม
- **ปิดกลุ่มใน §10 = เงียบทั้ง in-app และ push** (ค่าเดียวกันคุมสองทาง)
- เป็น **per-เครื่อง** ไม่ใช่ per-บัญชี — เครื่องเดียวใช้หลายคนได้ (มือถือโรงเรียน) ⇒ สวิตช์คุม "อุปกรณ์นี้"
  ส่วนจำนวนที่แสดงคือทุกอุปกรณ์ของบัญชี · **logging-in ใหม่บนเครื่องเดิม = ย้ายปลายทาง push มาที่ผู้ใช้ใหม่**
- **iOS/iPadOS ต้องติดตั้งลงหน้าจอก่อน** (Safari บนแท็บธรรมดาไม่มี `PushManager`) ⇒ UI ต้องบอกให้ติดตั้งก่อน
  ไม่ใช่โชว์ปุ่มที่กดแล้วเงียบ · **Firefox/Chrome desktop + Android ใช้ได้ทันทีโดยไม่ต้องติดตั้ง**
- ⚠️ **ต้องมี HTTPS** — clone ที่ยังเสิร์ฟ HTTP จะไม่ทำงานเลยโดยไม่มี error ให้เห็น
- ⚠️ **โหมดพักงาน:** ถ้า `VAPID_PUBLIC_KEY` ว่าง เซิร์ฟเวอร์จะ**ซ่อนการ์ดทั้งใบ** และไม่ส่ง push เลย
  (in-app ยังทำงาน) — เป็นสวิตช์ปิดฉุกเฉินที่ไม่ต้อง deploy โค้ด

## ❌ Out of Scope (ไม่ทำในเวอร์ชันนี้)

- Discord Bot — ไม่มีในระบบนี้ (โปรเจคเก่ามี แต่ PIRIvoice **ไม่รวม**)
- การเชื่อมต่อ OAuth กับ Discord/Google (ยังไม่มี)
- ระบบการเงิน/บัญชี (finance) — ไม่เกี่ยวข้อง
- ระบบตารางเรียน/ตารางสอน (schedule)
- ระบบงาน/การบ้าน (tasks/daily notes)
- **Mobile App แบบเนทีฟ** (ขึ้น App Store / Play Store) — ⚠️ **ไม่รวม PWA**
  → **PWA (ติดตั้งลงหน้าจอจากเบราว์เซอร์) อยู่ใน Scope** ตาม §15 เพราะเป็นเว็บตัวเดิม ไม่ใช่แอพใหม่
- Multi-language (ภาษาไทยอย่างเดียว)
- ระบบแชทระหว่างผู้แจ้ง-ผู้รับ
- การแจ้งเตือนผ่าน Line/Discord/Email

## 📝 หมายเหตุการตัดสินใจ

    `target="_blank"`** — เหตุผลคือตอนติดตั้งเป็น PWA (ตอนนี้ทำได้แล้ว) การเปิดแท็บใหม่จะพาผู้ใช้
    *หลุดออกจากแอป* · ข้อความบนการ์ดจึงห้ามสัญญาว่า "เปิดแท็บใหม่" (จะกลายเป็นคำโกหกทันทีที่มีคนเติม
    `_blank` กลับ — เทสต์ล็อกทั้งสองด้านไว้แล้ว) · **ข้อมูลนิ่ง ไม่ผูกกับ API** ⇒ ขึ้นได้แม้ระบบเราล่ม
  - **ยุบบล็อกที่ว่างในหน้าแรก (2 ต.ค.):** เจ้าของระบบรายงานว่า *"ตอนไม่มีเรื่องรอตอบ มันใหญ่มาก"*
    ⇒ บล็อกที่ว่างเป็นปกติเหลือ **แถวเดียว 44dp** · เลือก **"ยุบ" ไม่ใช่ "ซ่อน"** เพราะความว่างของ

    ไม่ใช่ลบทิ้ง) และ **"รอฉันตอบ" ยุบเฉพาะเมื่อทั้งเรื่องค้างและยังไม่อ่านเป็นศูนย์**
    ⇒ ทั้งชุดถูกแยกเป็นฟังก์ชันบริสุทธิ์ `types/home.ts` + ตารางความจริง `homeEmptyCollapse.spec.ts`
    และ **แก้บั๊กที่พบระหว่างทาง**: แดชบอร์ดเคยขึ้นหัวการ์ดลอยเมื่อไม่มีข้อมูล (ตอนนี้ซ่อน)

  ⇒ ข้อความเดิมที่ค้างในหัวข้อ Out of Scope ถูกลบ ไม่ใช่ปล่อยไว้ให้ขัดกันเอง

  PWA) · แยก **"Mobile App เนทีฟ" ออกจาก "PWA"** ให้ชัด เพราะของเดิมบรรทัดเดียวห้ามทั้งคู่ ทำให้เข้าใจผิดว่า
