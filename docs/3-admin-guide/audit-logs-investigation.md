# ตรวจสอบย้อนหลังด้วยบันทึกการใช้งาน

บทนี้อธิบายวิธีใช้หน้า **บันทึกการใช้งาน** เพื่อตอบคำถามว่าใครทำอะไร เมื่อไร และก่อน-หลังต่างกันอย่างไร
ใช้เมื่อข้อมูลหาย มีการแก้ผิด หรือต้องพิสูจน์ว่าเหตุการณ์หนึ่งเกิดขึ้นจริง

## ใครใช้บทนี้

ผู้มีสิทธิ์ `VIEW_AUDIT_LOG` และมีขอบเขตข้อมูลระดับโรงเรียน
ในทางปฏิบัติคือผู้ดูแลระบบ ครูสภานักเรียน และประธานสภา

ครูทั่วไปและประธานระดับเปิดหน้านี้ไม่ได้ แม้จะได้รับสิทธิ์ เพราะบันทึกการใช้งานเป็นข้อมูลข้ามระดับชั้น
ระบบตอบ **คุณไม่มีสิทธิ์ดูบันทึกการใช้งาน**

## ก่อนเริ่ม

- รู้ช่วงเวลาโดยประมาณของเหตุการณ์ ยิ่งแคบยิ่งค้นเร็ว
- รู้ชนิดข้อมูลที่สงสัย เช่น `student`, `issue`, `announcement`
- เข้าใจว่าระบบบันทึกทุกคำขอที่มีผลกับข้อมูล ไม่ได้บันทึกเฉพาะการแก้ไข
- ตัวเลข `id` ในคอลัมน์ข้อมูลคือรหัสในฐานข้อมูล ไม่ใช่รหัสนักเรียน

## ค้นหาเหตุการณ์ตามช่วงเวลา

1. เปิด **เพิ่มเติม**
2. ในกลุ่ม **โรงเรียน** เลือก **บันทึกการใช้งาน**
3. กรอก **จากวันที่** และ **ถึงวันที่** เป็นวันที่ตามเวลาไทย
4. กดปุ่มโหลดหรือเปลี่ยนหน้า ระบบค้นให้ทันทีเมื่อเปลี่ยนตัวกรอง

ระบบตีความวันที่เป็นเขตเวลา `Asia/Bangkok` ทั้งสองช่อง
ถ้ากรอกเฉพาะ **จากวันที่** จะเห็นทุกอย่างตั้งแต่วันนั้นจนถึงปัจจุบัน
ถ้ากรอกเฉพาะ **ถึงวันที่** จะเห็นทุกอย่างก่อนวันนั้น

## หาว่าใครแก้ข้อมูลรายการนี้

1. เปิด **บันทึกการใช้งาน**
2. ที่ช่อง **ชนิดข้อมูล** พิมพ์ชนิด เช่น `student`
3. ถ้ารู้รหัสในฐานข้อมูล ให้ค้นในช่อง **ค้นหา (ผู้ใช้/error)** ไม่ได้ เพราะช่องนั้นค้นชื่อผู้ใช้และข้อความผิดพลาด
4. อ่านคอลัมน์ **ข้อมูล** ซึ่งแสดง `ชนิด #รหัส` แล้วหาคนที่ตรงกับเหตุการณ์
5. กดลูกศรท้ายแถวเพื่อเปิด **ค่าเดิม (old_values)** และ **ค่าใหม่ (new_values)**

ถ้าต้องการดูเฉพาะรายการที่แก้สำเร็จ เลือก **สถานะ** เป็น **สำเร็จ**
ถ้าต้องการดูเฉพาะที่ล้มเหลว เลือก **ผิดพลาด**

## ตามรอยผู้ใช้คนหนึ่ง

1. กรอกชื่อผู้ใช้ในช่อง **ค้นหา (ผู้ใช้/error)**
2. ระบบค้นทั้งชื่อผู้ใช้และข้อความผิดพลาด ชื่อที่ตรงกับข้อความ error อาจติดมาด้วย
3. ประกอบกับ **จากวันที่** และ **ถึงวันที่** เพื่อจำกัดช่วง
4. เปิดรายละเอียดของแถวที่น่าสงสัย

ชื่อที่ใช้ค้นคือชื่อผู้ใช้ที่ใช้ล็อกอิน ไม่ใช่ชื่อ-นามสกุล
ถ้าผู้ใช้ล็อกอินด้วยรหัสนักเรียน ให้ค้นด้วยรหัสนักเรียน

## ตามรอยข้อผิดพลาด

1. เลือก **สถานะ** เป็น **ผิดพลาด**
2. ถ้ารู้ข้อความคร่าว ๆ ให้พิมพ์บางส่วนในช่อง **ค้นหา (ผู้ใช้/error)**
3. กดลูกศรท้ายแถว แล้วอ่านส่วน **ข้อผิดพลาด**
4. ดูเวลาและชื่อผู้ใช้ร่วมกัน เพื่อแยกว่าล้มเหลวเพราะสิทธิ์ ข้อมูลไม่ถูกต้อง หรือระบบผิดพลาด

สถานะ **บางส่วน** หมายถึงคำขอสำเร็จบางส่วนและล้มเหลวบางส่วน
งานนำเข้า Excel ใช้สถานะนี้เมื่อมีบางแถวถูกข้าม

## อ่านค่าเดิมและค่าใหม่ให้ถูก

ค่าเดิมและค่าใหม่เก็บเป็น JSON ของเฉพาะฟิลด์ที่เปลี่ยน
ถ้าแถวไม่มีค่าเดิมเลย มักเป็นการสร้างข้อมูลใหม่
ถ้าไม่มีค่าใหม่เลย มักเป็นการลบ ซึ่งในระบบนี้คือการตั้ง `deleted_at`

ตัวอย่างการอ่าน

| สถานการณ์ | สิ่งที่เห็นในค่าเดิม / ค่าใหม่ |
|---|---|
| เปลี่ยนตำแหน่งนักเรียน | `class_role` เดิมและใหม่ พร้อม `permissions` ที่คำนวณใหม่ |
| แก้ประกาศ | ชื่อหรือเนื้อหาเดิมและใหม่ |
| ลบนักเรียน | `deleted_at` เป็นค่าว่างในค่าเดิม และเป็นเวลาที่ลบในค่าใหม่ |
| ตั้งปีปัจจุบัน | ค่าใหม่มี `year_be` และ `is_current` |

ระบบไม่ได้เก็บสำเนาทั้งแถวไว้ทุกครั้ง เก็บเฉพาะฟิลด์ที่เปลี่ยนในคำขอนั้น
การย้อนประวัติหลายครั้งต้องไล่อ่านทีละรายการจากล่างขึ้นบน

## ตัวอย่างการสืบสามเหตุการณ์

### นักเรียนหายจากห้องหลังนำเข้า

1. กรอง **ชนิดข้อมูล** เป็น `student`
2. ใส่ช่วงวันที่มีการนำเข้า
3. มองหาการกระทำ **นำเข้าสำเร็จ** ในช่วงเวลาเดียวกัน
4. เปิดรายการ **แก้ไขนักเรียน** ของคนที่หาย แล้วดูว่าห้องเปลี่ยนไปที่ใด

ถ้าไม่พบการแก้ไขเลย ให้ตรวจว่ารายชื่อถูกสร้างในปีอื่นหรือไม่ โดยค้นรายการ **แก้ไขนักเรียน** ของคนนั้นทั้งปี

### ประกาศถูกแก้ทั้งที่ไม่มีใครสั่ง

1. กรอง **ชนิดข้อมูล** เป็น `announcement`
2. เปิดรายการ **แก้ไขประกาศ** ในช่วงที่เนื้อหาเปลี่ยน
3. ดูชื่อผู้ใช้ เวลา และ IP ในแถวนั้น

### เรื่องถูกปิดทั้งที่ยังไม่ได้แก้

1. กรอง **ชนิดข้อมูล** เป็น `issue`
2. มองหาการกระทำ **ปิดเรื่อง** ในช่วงที่สถานะเปลี่ยน
3. เปิดค่าใหม่เพื่อดูสถานะปลายทางและหมายเหตุ
4. ถ้าเป็นการปิดโดยระบบ ให้ตรวจว่ามีงานอัตโนมัติทำงานในช่วงนั้นหรือไม่

## ป้ายการกระทำที่พบบ่อย

หน้าจอแปลรหัสการกระทำที่รู้จักเป็นภาษาไทย และแสดงรหัสจริงคู่กันเพื่อใช้อ้างอิง

| รหัส | ความหมาย | หน้าจอแปลให้หรือยัง |
|---|---|---|
| `login` | เข้าสู่ระบบ | แปลแล้ว |
| `CREATE_ISSUE` | แจ้งเรื่องใหม่ | แปลแล้ว |
| `ACCEPT_ISSUE` | รับเรื่อง | แปลแล้ว |
| `ESCALATE_ISSUE` | ส่งต่อให้ระดับสูงขึ้น | แปลแล้ว |
| `RESOLVE_ISSUE` | ปิดเรื่อง | แปลแล้ว |
| `UPDATE_STUDENT` | แก้ไขนักเรียน | แปลแล้ว |
| `CREATE_STUDENT` | สร้างบัญชีนักเรียนรายคน | ยังไม่แปล |
| `MOVE_STUDENTS` | ย้ายห้องนักเรียน | ยังไม่แปล |
| `UPDATE_QUIET_HOURS` | ตั้งช่วงเวลาไม่ส่งแจ้งเตือน | แปลแล้ว |
| `SET_CURRENT_YEAR` | ตั้งปีปัจจุบัน | ยังไม่แปล |
| `APPLY_ROLLOVER` | เลื่อนชั้นทั้งโรงเรียน | ยังไม่แปล |
| `READ_AUDIT_LOGS` | ดูบันทึกการใช้งาน | แปลแล้ว |

รหัสที่ยังไม่มีป้ายไทยจะแสดงเป็นภาษาอังกฤษตามจริง เช่นการกระทำของบอร์ด การย้ายห้อง และการขึ้นปี
นี่ไม่ใช่ข้อมูลสูญหาย แต่เป็นรายการที่ยังไม่ได้แปลบนหน้าจอ ให้ยึดรหัสจริงเป็นหลัก

## ระบบทำอะไรเบื้องหลัง

- ทุกคำขอที่เขียนข้อมูลบันทึกในทรานแซกชันเดียวกับการเปลี่ยนแปลง ถ้าการเปลี่ยนล้มเหลว บันทึกก็ไม่เกิด
- การอ่านข้อมูลบางประเภทก็ถูกบันทึก เช่น `READ_STUDENTS` `READ_DASHBOARD` `READ_AUDIT_LOGS`
- การบันทึกการอ่านเป็นแบบพยายามที่สุด ถ้าเขียนบันทึกไม่ได้ คำขอหลักยังสำเร็จ
- ระบบเก็บเวลาเป็น UTC และแสดงเป็นเวลาไทยเมื่ออ่าน
- ระบบกรองตามขอบเขตก่อนคืนผล ครูที่เห็นเฉพาะระดับชั้นจึงไม่เห็นบันทึกของระดับอื่น
- การค้นหาด้วยคำค้นตรงกับชื่อผู้ใช้หรือข้อความผิดพลาดเท่านั้น ไม่ค้นในค่าเดิมและค่าใหม่
- ระบบแสดงหน้ารอบละ 20 รายการ และรับค่าจำนวนต่อหน้าได้สูงสุด 200 ผ่าน API
- ทุกครั้งที่เปิดหน้านี้ ระบบบันทึก `READ_AUDIT_LOGS` เพิ่มอีกหนึ่งรายการ

## ข้อจำกัดและข้อควรระวัง

- หน้าจอไม่มีปุ่มแก้หรือลบบันทึก และไม่ควรแก้ที่ฐานข้อมูลเพราะทำให้หลักฐานขาดตอน
- ไม่มีการแจ้งเตือนเมื่อมีเหตุการณ์ผิดปกติ ต้องเปิดดูเอง
- ช่องค้นหาไม่ค้นในเนื้อหาค่าเดิมและค่าใหม่ ต้องเปิดรายละเอียดอ่านเอง
- ระบบเก็บเฉพาะฟิลด์ที่เปลี่ยน ไม่ได้เก็บภาพข้อมูลทั้งแถวก่อนแก้
- บันทึกของระบบเก่าอาจไม่มี IP หรือชื่อผู้ใช้ ถ้าคำขอมาจากงานอัตโนมัติ
- วันที่ถูกตีความเป็นเวลาไทย ถ้าทีมตรวจอยู่ต่างเขตเวลาให้แปลงก่อนสรุป
- หน้านี้แสดงทีละ 20 รายการ การไล่หาช่วงยาวต้องใช้ตัวกรองวันที่ช่วย
- บันทึกไม่ได้ผูกกับตารางอื่นด้วย foreign key ข้อมูลที่ถูกลบจึงยังอ้างถึงได้

## แก้ไขปัญหาและคำถามที่พบบ่อย

**ถาม: เปิดหน้าบันทึกการใช้งานไม่ได้**
ตอบ: ต้องมีทั้งสิทธิ์ `VIEW_AUDIT_LOG` และตำแหน่งระดับโรงเรียน
ถ้าเป็นครูหรือประธานระดับ ให้ขอให้ผู้ดูแลระบบเป็นผู้ตรวจ

**ถาม: รู้รหัสนักเรียนแต่ค้นไม่เจอ**
ตอบ: ช่องค้นหาดูที่ชื่อผู้ใช้กับข้อความผิดพลาด ไม่ได้ดูที่ชื่อหรือรหัสนักเรียน
ให้กรองชนิดข้อมูลเป็น `student` แล้วเปิดรายการ **แก้ไขนักเรียน** เพื่อหาคนที่ตรงกัน

**ถาม: พบว่ามีคนแก้ข้อมูล แต่ค่าเดิมว่าง**
ตอบ: รายการนั้นอาจเป็นการสร้างข้อมูลใหม่ ไม่ใช่การแก้
ถ้าเป็นการลบ ค่าใหม่จะมี `deleted_at` และค่าเดิมว่าง

**ถาม: บันทึกมีเฉพาะบางช่วง ไม่ครบทั้งปี**
ตอบ: ตัวกรองวันที่ยังค้างอยู่ ให้ล้าง **จากวันที่** และ **ถึงวันที่**
หรือระบบอาจเริ่มเก็บข้อมูลหลังวันติดตั้ง จึงไม่มีข้อมูลก่อนหน้านั้นเลย

**ถาม: ต้องการดูว่ามีใครเปิดข้อมูลนักเรียนบ้าง**
ตอบ: กรองการกระทำเป็น `READ_STUDENTS` ถ้าต้องการดูรายคนให้เพิ่มช่วงวันที่
การอ่านจำนวนมากในเวลาสั้นอาจเป็นสัญญาณของการดึงข้อมูลผิดวัตถุประสงค์

**ถาม: เอารหัสการกระทำไปใช้ต่อได้ไหม**
ตอบ: ได้ รหัสในคอลัมน์การกระทำตรงกับฐานข้อมูลและใช้กรองใน API ได้
แต่ห้ามสรุปรหัสใหม่เองโดยไม่ตรวจว่า backend รองรับ

**ถาม: บันทึกหายไปหลังกู้ฐานข้อมูล**
ตอบ: การกู้คืนย้อนกลับจะทำให้บันทึกหลังจากจุดสำรองหายไปด้วย
ให้เก็บไฟล์สำรองและบันทึกช่วงเวลาที่กู้ไว้ในรายงานเหตุการณ์
