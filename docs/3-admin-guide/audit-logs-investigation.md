# ตรวจสอบย้อนหลังด้วยบันทึกการใช้งาน

ข้อมูลหาย มีคนแก้อะไรแปลก ๆ หรือต้องพิสูจน์ว่าเหตุการณ์หนึ่งเกิดจริง
ที่ที่ตอบได้คือหน้า **บันทึกการใช้งาน** ซึ่งเก็บทุกการเปลี่ยนแปลงพร้อมคนทำ เวลา และค่าเดิม–ค่าใหม่

- ทุกคำขอที่เขียนข้อมูลถูกบันทึกในทรานแซกชันเดียวกับการเปลี่ยน
- ค้นด้วยช่วงวันที่ ชนิดข้อมูล ชื่อผู้ใช้ หรือสถานะ
- ตัวเลข `id` ในคอลัมน์ข้อมูลคือรหัสในฐานข้อมูล ไม่ใช่รหัสนักเรียน

## ใครใช้บทนี้

คนที่มีสิทธิ์ `VIEW_AUDIT_LOG` และมีขอบเขตข้อมูลระดับโรงเรียน
ในทางปฏิบัติคือผู้ดูแลระบบ ครูสภานักเรียน และประธานสภา

ครูทั่วไปและประธานระดับเปิดหน้านี้ไม่ได้ แม้ได้สิทธิ์ เพราะบันทึกการใช้งานเป็นข้อมูลข้ามระดับชั้น
ระบบจะตอบ **คุณไม่มีสิทธิ์ดูบันทึกการใช้งาน**

ก่อนเริ่ม ให้เตรียมสามอย่างนี้

- ช่วงเวลาโดยประมาณของเหตุการณ์ ยิ่งแคบยิ่งค้นเร็ว
- ชนิดข้อมูลที่สงสัย เช่น `student` `issue` `announcement`
- เข้าใจว่าในนั้นบันทึกทุกคำขอที่มีผลกับข้อมูล ไม่ได้เก็บเฉพาะการแก้ไข

## ค้นหาเหตุการณ์ตามช่วงเวลา

**ทางเข้า:** แท็บ **เพิ่มเติม** ➔ กลุ่ม **โรงเรียน** ➔ **บันทึกการใช้งาน**

กรอก **จากวันที่** และ **ถึงวันที่** เป็นวันที่ตามเวลาไทย
ระบบค้นให้ทันทีเมื่อเปลี่ยนตัวกรอง ไม่ต้องกดปุ่ม

วันที่ถูกตีความเป็นเขตเวลา `Asia/Bangkok` ทั้งสองช่อง
กรอกแค่ **จากวันที่** จะเห็นทุกอย่างตั้งแต่วันนั้นถึงตอนนี้
กรอกแค่ **ถึงวันที่** จะเห็นทุกอย่างก่อนวันนั้น

## หาว่าใครแก้ข้อมูลรายการนี้

1. **กรอง ชนิดข้อมูล** พิมพ์ชนิดที่สงสัย เช่น `student`
2. **อ่านคอลัมน์ ข้อมูล** ซึ่งแสดง `ชนิด #รหัส`
3. **กดลูกศรท้ายแถว** เพื่อเปิด **ค่าเดิม (old_values)** และ **ค่าใหม่ (new_values)**
4. **กรอง สถานะ** เป็น **สำเร็จ** ถ้าอยากดูเฉพาะที่สำเร็จ หรือ **ผิดพลาด** ถ้าอยากดูที่ล้มเหลว

ช่อง **ค้นหา (ผู้ใช้/error)** ใช้หาชื่อผู้ใช้กับข้อความผิดพลาด ไม่ได้ค้นรหัสในฐานข้อมูล

## ตามรอยผู้ใช้คนหนึ่ง

1. **กรอกชื่อผู้ใช้** ในช่อง **ค้นหา (ผู้ใช้/error)**
2. **ประกอบกับช่วงวันที่** เพื่อจำกัดขอบเขต
3. **เปิดรายละเอียด** ของแถวที่น่าสงสัย

ช่องค้นหาดูทั้งชื่อผู้ใช้และข้อความผิดพลาด เลยอาจมีชื่อที่บังเอิญตรงกับข้อความ error ติดมาด้วย
ชื่อที่ใช้ค้นคือชื่อผู้ใช้ที่ล็อกอิน ไม่ใช่ชื่อ–นามสกุล ถ้าล็อกอินด้วยรหัสนักเรียน ให้ค้นด้วยรหัสนักเรียน

## ตามรอยข้อผิดพลาด

**ทางเข้า:** เลือก **สถานะ** เป็น **ผิดพลาด** ➔ พิมพ์ข้อความคร่าว ๆ ในช่องค้นหา (ถ้ารู้) ➔ กดลูกศรท้ายแถว ➔ อ่านส่วน **ข้อผิดพลาด**

ดูเวลากับชื่อผู้ใช้ประกอบกัน จะแยกว่าล้มเหลวเพราะสิทธิ์ ข้อมูลไม่ถูกต้อง หรือระบบมีปัญหา

สถานะ **บางส่วน** แปลว่าคำขอสำเร็จบางส่วนและล้มเหลวบางส่วน
งานนำเข้า Excel ใช้สถานะนี้เมื่อมีบางแถวถูกข้าม

## อ่านค่าเดิมและค่าใหม่ให้ถูก

ค่าเดิมและค่าใหม่เก็บเป็น JSON ของเฉพาะฟิลด์ที่เปลี่ยน
ถ้าไม่มีค่าเดิมเลย มักเป็นการสร้างข้อมูลใหม่
ถ้าไม่มีค่าใหม่เลย มักเป็นการลบ ซึ่งในระบบนี้คือการตั้ง `deleted_at`

ตัวอย่างการอ่าน

| สถานการณ์ | สิ่งที่เห็นในค่าเดิม / ค่าใหม่ |
|---|---|
| เปลี่ยนตำแหน่งนักเรียน | `class_role` เดิมและใหม่ พร้อม `permissions` ที่คำนวณใหม่ |
| แก้ประกาศ | ชื่อหรือเนื้อหาเดิมและใหม่ |
| ลบนักเรียน | `deleted_at` เป็นค่าว่างในค่าเดิม และเป็นเวลาที่ลบในค่าใหม่ |
| ตั้งปีปัจจุบัน | ค่าใหม่มี `year_be` และ `is_current` |

ระบบไม่ได้เก็บสำเนาทั้งแถวไว้ทุกครั้ง เก็บเฉพาะฟิลด์ที่เปลี่ยนในคำขอนั้น
จะย้อนประวัติหลายครั้งต้องไล่อ่านทีละรายการจากล่างขึ้นบน

## ตัวอย่างการสืบสามเหตุการณ์

### นักเรียนหายจากห้องหลังนำเข้า

1. **กรอง ชนิดข้อมูล เป็น `student`**
2. **ใส่ช่วงวันที่มีการนำเข้า**
3. **มองหาการกระทำ นำเข้าสำเร็จ** ในช่วงเวลาเดียวกัน
4. **เปิด แก้ไขนักเรียน** ของคนที่หาย แล้วดูว่าห้องเปลี่ยนไปที่ไหน

ถ้าไม่พบการแก้ไขเลย ให้ดูว่าคนนั้นถูกสร้างในปีอื่นไหม โดยค้น **แก้ไขนักเรียน** ของคนนั้นทั้งปี

### ประกาศถูกแก้ทั้งที่ไม่มีใครสั่ง

1. **กรอง ชนิดข้อมูล เป็น `announcement`**
2. **เปิด แก้ไขประกาศ** ในช่วงที่เนื้อหาเปลี่ยน
3. **ดูชื่อผู้ใช้ เวลา และ IP** ในแถวนั้น

### เรื่องถูกปิดทั้งที่ยังไม่ได้แก้

1. **กรอง ชนิดข้อมูล เป็น `issue`**
2. **มองหา ปิดเรื่อง** ในช่วงที่สถานะเปลี่ยน
3. **เปิดค่าใหม่** เพื่อดูสถานะปลายทางและหมายเหตุ
4. ถ้าเป็นการปิดโดยระบบ ให้ดูว่ามีงานอัตโนมัติทำงานในช่วงนั้นไหม

## ป้ายการกระทำที่เจอบ่อย

หน้าจอแปลรหัสที่รู้จักเป็นภาษาไทย และแสดงรหัสจริงคู่กันเพื่อใช้อ้างอิง

| รหัส | ความหมาย | หน้าจอแปลให้หรือยัง |
|---|---|---|
| `login` | เข้าสู่ระบบ | แปลแล้ว |
| `CREATE_ISSUE` | แจ้งเรื่องใหม่ | แปลแล้ว |
| `ACCEPT_ISSUE` | รับเรื่อง | แปลแล้ว |
| `ESCALATE_ISSUE` | ส่งต่อให้ระดับสูงขึ้น | แปลแล้ว |
| `RESOLVE_ISSUE` | ปิดเรื่อง | แปลแล้ว |
| `UPDATE_STUDENT` | แก้ไขนักเรียน | แปลแล้ว |
| `CREATE_STUDENT` | สร้างบัญชีนักเรียนรายคน | ยังไม่แปล |
| `MOVE_STUDENTS` | ย้ายห้องนักเรียน | ยังไม่แปล |
| `UPDATE_QUIET_HOURS` | ตั้งช่วงเวลาไม่ส่งแจ้งเตือน | แปลแล้ว |
| `SET_CURRENT_YEAR` | ตั้งปีปัจจุบัน | ยังไม่แปล |
| `APPLY_ROLLOVER` | เลื่อนชั้นทั้งโรงเรียน | ยังไม่แปล |
| `READ_AUDIT_LOGS` | ดูบันทึกการใช้งาน | แปลแล้ว |

รหัสที่ยังไม่มีป้ายไทยจะแสดงเป็นภาษาอังกฤษตามจริง เช่นการกระทำของบอร์ด การย้ายห้อง และการขึ้นปี
ไม่ใช่ข้อมูลหาย แต่เป็นรายการที่หน้าจอยังไม่ได้แปล ให้ยึดรหัสจริงเป็นหลัก

## ระบบทำอะไรเบื้องหลัง

- ทุกคำขอที่เขียนข้อมูลบันทึกในทรานแซกชันเดียวกัน ถ้าการเปลี่ยนล้มเหลว บันทึกก็ไม่เกิด
- การอ่านข้อมูลบางประเภทก็ถูกบันทึก เช่น `READ_STUDENTS` `READ_DASHBOARD` `READ_AUDIT_LOGS`
- การบันทึกการอ่านเป็นแบบพยายามที่สุด ถ้าเขียนบันทึกไม่ได้ คำขอหลักยังสำเร็จ
- ระบบเก็บเวลาเป็น UTC และแปลงเป็นเวลาไทยตอนแสดง
- ระบบกรองตามขอบเขตก่อนคืนผล ครูที่เห็นเฉพาะระดับชั้นจึงไม่เห็นบันทึกของระดับอื่น
- ค้นหาคำค้นได้เฉพาะชื่อผู้ใช้หรือข้อความผิดพลาด ไม่ค้นในค่าเดิมและค่าใหม่
- หน้าจอแสดงรอบละ 20 รายการ และ API รับจำนวนต่อหน้าได้สูงสุด 200
- ทุกครั้งที่เปิดหน้านี้ ระบบบันทึก `READ_AUDIT_LOGS` เพิ่มอีกหนึ่งรายการ

## ข้อจำกัดและข้อควรระวัง

::: warning อย่าแก้บันทึกที่ฐานข้อมูล
หน้าจอไม่มีปุ่มแก้หรือลบ และถ้าไปแก้ที่ฐานข้อมูล หลักฐานจะขาดตอน
ถ้าต้องการเก็บหลักฐาน ให้ส่งออกหรือจดบันทึกไว้แทน
:::

- ไม่มีการแจ้งเตือนเมื่อมีเหตุการณ์ผิดปกติ ต้องเปิดดูเอง
- ช่องค้นหาไม่ค้นในเนื้อหาค่าเดิมและค่าใหม่ ต้องเปิดรายละเอียดอ่านเอง
- ระบบเก็บเฉพาะฟิลด์ที่เปลี่ยน ไม่ได้เก็บภาพทั้งแถวก่อนแก้
- บันทึกของงานอัตโนมัติอาจไม่มี IP หรือชื่อผู้ใช้
- วันที่ถูกตีความเป็นเวลาไทย ถ้าตรวจอยู่ต่างเขตเวลาให้แปลงก่อนสรุป
- หน้านี้แสดงทีละ 20 รายการ การหาช่วงยาวต้องใช้ตัวกรองวันที่ช่วย
- บันทึกไม่ได้ผูกกับตารางอื่นด้วย foreign key ข้อมูลที่ถูกลบจึงยังอ้างถึงได้

## ติดปัญหาตรงไหน? ดูวิธีแก้ตรงนี้เลย

**Q: เปิดหน้าบันทึกการใช้งานไม่ได้?**

👉 **วิธีแก้:** ต้องมีทั้งสิทธิ์ `VIEW_AUDIT_LOG` และตำแหน่งระดับโรงเรียน ถ้าเป็นครูหรือประธานระดับ ให้ขอให้ผู้ดูแลระบบเป็นคนตรวจ

**Q: รู้รหัสนักเรียนแต่ค้นไม่เจอ?**

👉 **วิธีแก้:** ช่องค้นหาดูที่ชื่อผู้ใช้กับข้อความผิดพลาด ไม่ได้ดูที่ชื่อหรือรหัสนักเรียน ให้กรองชนิดข้อมูลเป็น `student` แล้วเปิดรายการ **แก้ไขนักเรียน** เพื่อหาคนที่ตรงกัน

**Q: พบว่ามีคนแก้ข้อมูล แต่ค่าเดิมว่าง?**

👉 **วิธีแก้:** รายการนั้นอาจเป็นการสร้างข้อมูลใหม่ ไม่ใช่การแก้ ถ้าเป็นการลบ ค่าใหม่จะมี `deleted_at` และค่าเดิมว่าง

**Q: บันทึกมีเฉพาะบางช่วง ไม่ครบทั้งปี?**

👉 **วิธีแก้:** ตัวกรองวันที่อาจยังค้างอยู่ ให้ล้าง **จากวันที่** และ **ถึงวันที่** หรือระบบอาจเริ่มเก็บหลังวันติดตั้ง เลยไม่มีข้อมูลก่อนหน้านั้น

**Q: อยากดูว่ามีใครเปิดข้อมูลนักเรียนบ้าง?**

👉 **วิธีแก้:** กรองการกระทำเป็น `READ_STUDENTS` และเพิ่มช่วงวันที่ถ้าจะดูรายคน การอ่านจำนวนมากในเวลาสั้นอาจเป็นสัญญาณของการดึงข้อมูลผิดวัตถุประสงค์

**Q: เอารหัสการกระทำไปใช้ต่อได้ไหม?**

👉 **วิธีแก้:** ได้ รหัสในคอลัมน์การกระทำตรงกับฐานข้อมูลและใช้กรองใน API ได้ แต่ห้ามตั้งรหัสใหม่เองโดยไม่เช็กว่า backend รองรับ

**Q: บันทึกหายไปหลังกู้ฐานข้อมูล?**

👉 **วิธีแก้:** การกู้คืนย้อนหลังทำให้บันทึกหลังจากจุดสำรองหายไปด้วย ให้เก็บไฟล์สำรองและจดช่วงเวลาที่กู้ไว้ในรายงานเหตุการณ์
