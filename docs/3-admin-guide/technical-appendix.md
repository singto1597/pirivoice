# ภาคผนวกทางเทคนิค

บทนี้แปลชื่อเทคนิคที่โผล่ในคู่มือ ในบันทึก และในหน้าจอ ให้กลับมาหาเรื่องเดียวกันได้
— ชื่อสิทธิ์ ชื่อตาราง ชื่อฟิลด์ ค่าสถานะ และปลายทาง API ที่ไม่มีปุ่มให้กด

- ใช้เมื่อต้องตอบคำถามว่า "ค่าที่เห็นในฐานข้อมูลแปลว่าอะไร"
- ทุกแถวในหน้านี้อ้างจากโค้ดจริง ไม่ใช่ชื่อที่แต่งขึ้นมาเล่า
- ใครทำงานประจำวันไม่ต้องอ่านบทนี้ ภาคผนวกมีไว้ตอบคำถาม Technical เท่านั้น

## ใครใช้บทนี้

ผู้ดูแลระบบ ครูสภานักเรียน ประธานสภา และนักพัฒนาที่ต้องตอบคำถาม Technical
ใช้สิทธิ์เดิมของเล่มนี้ ไม่มีสิทธิ์ใหม่เพิ่มขึ้นมา

ก่อนเริ่ม ควรเปิดคู่มือเล่ม 2 คู่ไว้ด้วย
เพราะภาคผนวกนี้ไม่ได้สอนงาน แต่ต่อชื่อเทคนิคเข้ากับคำที่บทเหล่านั้นใช้

## รหัสสิทธิ์กับคำที่หน้าจอใช้

ระบบเก็บสิทธิ์เป็นรหัสภาษาอังกฤษในชุดข้อมูลสิทธิ์ของสมาชิก แล้วใช้ค่าเดียวกันเปิด-ปิดเมนู
หน้าจอไม่เคยแสดงรหัสนี้ ผู้ใช้เห็นแค่ว่าเมนูขึ้นหรือไม่ขึ้น

| รหัสสิทธิ์ | แปลว่า | สิ่งที่ปลดล็อก |
|---|---|---|
| `SUBMIT_ISSUE` | แจ้งเรื่องได้ | ปุ่ม **แจ้งเรื่อง** |
| `VIEW_OWN_ISSUES` | ดูเรื่องของตัวเอง | แท็บเรื่องของฉัน |
| `RECEIVE_ISSUES` | รับเรื่องในระดับของเรา | ปุ่ม **รับเรื่อง + ตั้งเวลา** |
| `MANAGE_ISSUE_STEPS` | เพิ่มและปิดขั้นตอนในเรื่อง | ส่วน **ขั้นตอนการดำเนินงาน** |
| `SET_COUNTDOWN` | ตั้งและยืดกำหนดแก้ไข | ปุ่มตั้งวัน และ **ยืดเวลา** |
| `ESCALATE_ISSUE` | ส่งต่อเรื่องขึ้นระดับบน | เมนู **ส่งต่อไประดับบน** |
| `VIEW_LEVEL_PYRAMID` | เห็นเรื่องในระดับที่ดูแลอยู่ | คิว **ที่รับผิดชอบ** |
| `MANAGE_ANNOUNCEMENTS` | สร้าง แก้ และปลดระวางประกาศ | เมนู **จัดการประกาศ** |
| `MANAGE_EVENTS` | สร้างกิจกรรมและสแกนเช็คอิน | แท็บ **จัดการ** ในหน้า **กิจกรรม** |
| `MANAGE_STUDENTS` | ดูและแก้ข้อมูลนักเรียนในขอบเขตของเรา | **สมาชิก** **นำเข้านักเรียน** **ย้ายห้องนักเรียน** |
| `VIEW_DASHBOARD` | เปิดแดชบอร์ด | เมนู **แดชบอร์ด** |
| `MANAGE_SETTINGS` | ตั้งปีการศึกษา ภาคเรียน และระบบ | **ปีการศึกษา** **ภาคเรียน** |
| `VIEW_AUDIT_LOG` | เปิดบันทึกการใช้งาน | เมนู **บันทึกการใช้งาน** |

อีกกลุ่มที่หน้าตาเหมือนชื่อสิทธิ์แต่ไม่ใช่ คือค่าที่ขึ้นต้นด้วย `READ_`
อย่าง `READ_ISSUES` `READ_STUDENTS` `READ_ME` และ `READ_DASHBOARD_TRAFFIC`
ค่าเหล่านี้คือชื่อการอ่านที่ระบบบันทึกไว้ใน **บันทึกการใช้งาน** ตอนมีคนเปิดหน้านั้น
ไม่ได้แปลว่าต้องมีสิทธิ์ตัวนี้ก่อน หน้าจอใช้สิทธิ์ตัวอื่นในการเปิดอยู่แล้ว
และการบันทึกการอ่านเป็นแบบพยายามที่สุด ถ้าบันทึกพลาดคำขอยังสำเร็จตามปกติ

`is_admin` ไม่ใช่สิทธิ์รายข้อ แต่เป็นแฟล็กที่บอกว่า "ข้ามการตรวจสิทธิ์ทั้งหมด"
ค่ามาจากตำแหน่งใน `backend/config/roles.json` จึงไม่มีหน้าจอให้ตั้งแยก
ตำแหน่งที่ติดแฟล็กนี้คือ **ประธานสภา** **ครูสภานักเรียน** และ **ผู้ดูแลระบบ**

`SUPER_ADMIN_ID` ใน `.env` เป็นรหัสผู้ใช้ที่ข้ามทุกด่านเหมือนกัน
ใช้ตอนกู้ระบบกรณีไม่มีคนที่ติดแฟล็กนี้ล็อกอินได้ ตั้งได้ครั้งละหนึ่งคน

## ชื่อตารางที่คู่มือพูดถึง

คู่มือเล่ม 2 เขียนด้วยคำที่หน้าจอใช้ ตารางนี้เป็นคู่มือย้อนกลับเมื่อเจอชื่อในฐานข้อมูล

| ตาราง | เก็บอะไร | คู่มือเล่ม 2 เรียกมันว่าอะไร |
|---|---|---|
| `issues` | เรื่องทุกเรื่อง พร้อมสถานะและผู้รับปัจจุบัน | เรื่อง |
| `issue_steps` | ขั้นตอนการดำเนินงานในเรื่อง | ขั้นตอนการดำเนินงาน |
| `issue_countdowns` | กำหนดแก้ไขแต่ละรอบ พร้อมวันครบ | กำหนดแก้ไข |
| `issue_escalations` | ประวัติการส่งต่อระหว่างระดับ | ระดับที่ส่งต่อไป |
| `issue_status_history` | สถานะทุกครั้งที่เปลี่ยน | ประวัติในไทม์ไลน์ |
| `piri_boards` | กระทู้สาธารณะจากเรื่องที่อนุมัติแล้ว | บอร์ด |
| `piri_board_reports` | รายงานเนื้อหาที่คนกดแจ้ง | คิว **จัดการรายงาน** |
| `announcements` | ประกาศบนหน้าเว็บ | ประกาศ |
| `events` | กิจกรรม | กิจกรรม |
| `event_registrations` | การลงทะเบียนและเช็คอิน | รายชื่อผู้สมัคร |
| `students` | แถวสมาชิกของแต่ละปีการศึกษา | รายชื่อนักเรียน |
| `student_moves` | ประวัติการย้ายห้องภายในปี | การย้ายห้อง |
| `student_import_jobs` | งานนำเข้า Excel หนึ่งครั้ง | งานนำเข้า |
| `rollover_runs` | รอบการเลื่อนชั้นหนึ่งครั้ง | ประวัติการเลื่อนชั้น |
| `audit_logs` | ทุกการเปลี่ยนแปลงพร้อมคนทำ | บันทึกการใช้งาน |
| `app_settings` | ค่าตั้งทั้งระบบ เช่น ช่วงเวลาแจ้งเตือน | ตั้งค่าระบบ |

ฟิลด์ที่ถูกอ้างบ่อยในคู่มือ มีความหมายตรงตัวแบบนี้

| ฟิลด์ | แปลว่า |
|---|---|
| `issue_id` | รหัสของเรื่องในฐานข้อมูล ไม่ใช่รหัสนักเรียน |
| `current_assignee_id` | รหัสผู้ใช้ที่ถือเรื่องอยู่ |
| `current_level` | ระดับที่เรื่องอยู่ตอนนี้ (`room` `level` `council`) |
| `requested_destination` | ปลายทางที่ผู้แจ้งขอ (`normal` `vote` `talk`) |
| `staff_level` | ระดับชั้นที่ครูคนนั้นดูแล |
| `deleted_at` | เวลาที่ถูกนำออกแบบยังเก็บประวัติ |
| `retired_at` | เวลาที่ประกาศถูกปลดระวาง |

## ค่าสถานะในฐานข้อมูล

ค่าสถานะถูกเก็บเป็นภาษาอังกฤษ ส่วนหน้าจอแปลเป็นไทยทุกครั้งที่แสดง

**เรื่อง** — `pending` **รอรับเรื่อง** · `in_progress` **กำลังดำเนินการ** · `escalated` **ส่งต่อให้ระดับสูงขึ้น** · `resolved` **แก้ไขเสร็จ** · `rejected` **ถูกปฏิเสธ** · `cancelled` **ถูกยกเลิก**

**บอร์ด** — `active` ใช้งานอยู่ · `closed` ปิดประเด็น · `hidden` ถูกซ่อน

**รายงานเนื้อหา** — `open` **รอจัดการ** · `resolved` **ซ่อนแล้ว** · `dismissed` **ไม่ดำเนินการ**

**ประกาศ** — ระดับความสำคัญคือ `normal` `high` `urgent` ส่วนการปลดระวางดูจาก `retired_at` ที่มีค่าหรือว่าง ไม่ใช่คอลัมน์สถานะ

**กิจกรรม** — `draft` **ฉบับร่าง** · `published` **เผยแพร่แล้ว** · `cancelled` **ยกเลิกแล้ว**
การลบแยกจากสถานะและดูจาก `deleted_at`

**การลงทะเบียนกิจกรรม** — `registered` **ลงทะเบียนแล้ว** · `waitlisted` **คิวสำรอง** · `checked_in` **เช็คอินแล้ว** · `cancelled` **ยกเลิก**

**งานนำเข้า Excel** — `PENDING` รอคิว · `QUEUED` เข้าคิวแล้ว · `PROCESSING` กำลังประมวลผล · `COMPLETED` **เสร็จแล้ว** · `FAILED` **ล้มเหลว**

**รอบเลื่อนชั้น** — `PREVIEWED` **ดูแผนแล้ว** · `APPLIED` **ทำแล้ว** · `FAILED` **ล้มเหลว**

## การลบที่ไม่ลบข้อมูลจริง

ข้อมูลที่ต้องตอบย้อนหลังได้ ถูกลบแค่การติดเวลาไว้ที่ `deleted_at`
แถวยังอยู่ในตารางและทุกหน้าจอยังกรองแถวนั้นออก เพราะเงื่อนไขค้นหาทุกตัวมี `deleted_at IS NULL` กำกับ

ผลที่ตามมาสองข้อ ซึ่งเจอในงานจริงบ่อย

- ข้อมูลที่ "ลบแล้ว" ยังกินพื้นที่และยังนับเป็นแถวในตาราง ถ้าตัวเลขในฐานข้อมูลมากกว่าที่หน้าจอแสดง ให้คิดถึงข้อนี้ก่อน
- การกู้คืนทำได้โดยล้าง `deleted_at` ให้ว่าง หน้าจอไม่มีปุ่มนี้ ต้องใช้เครื่องมือฝั่งเทคนิค

ประกาศมีอีกชั้นคือ `retired_at` แปลว่า "เอาออกจากหน้าเว็บแต่ยังเก็บไว้เป็นประวัติ"
สองคอลัมน์นี้เป็นอิสระต่อกัน ปลดระวางแล้วลบ แล้วกู้คืน จะกลับมาเป็น **ปลดระวางแล้ว** ตามเดิม

::: warning ลบกับปลดระวางคนละเรื่อง
ถ้าอยากให้ประกาศหายจากหน้าเว็บแต่ยังดูย้อนหลังได้ ให้ใช้ **ปลดระวาง** ไม่ใช่ลบ
ลบแล้วกู้คืนได้ก็จริง แต่ระหว่างนั้นจะหายจากทั้งหน้าเว็บและรายการในหน้าจัดการ
:::

## บันทึกการใช้งานเขียนพร้อมการเปลี่ยนข้อมูล

ทุกคำขอที่เขียนข้อมูล จะเขียนแถวใน `audit_logs` อยู่ในธุรกรรมเดียวกับการเปลี่ยนข้อมูล
ถ้าการเปลี่ยนล้ม ธุรกรรมทั้งก้อนถูกยกเลิก บันทึกก็หายไปด้วย

ผลคือบันทึกกับข้อมูลตรงกันเสมอ ไม่มีสองกรณีที่หลุดได้

- บันทึกว่าสำเร็จ แต่ข้อมูลไม่ได้เปลี่ยน
- ข้อมูลเปลี่ยนแล้ว แต่ไม่มีบันทึกว่าใครทำ

การกระทำที่มีชื่อในบันทึก และสิ่งที่คู่มือเล่ม 2 เรียก

| ชื่อในบันทึก | เกิดตอนไหน |
|---|---|
| `ACCEPT_ISSUE` | กดรับเรื่องและตั้งกำหนด |
| `ESCALATE_ISSUE` | ส่งต่อขึ้นระดับบน |
| `CHANGE_DESTINATION` | เปลี่ยนปลายทางของเรื่อง |
| `RESOLVE_ISSUE` | ปิดเรื่อง |
| `REASSIGN_ISSUE` | มอบหมายเรื่องให้ผู้รับใหม่ |
| `APPROVE_TO_PUBLIC` | อนุมัติเรื่องขึ้นบอร์ดสาธารณะ |
| `HIDE_BOARD` · `HIDE_COMMENT` | ซ่อนกระทู้หรือคอมเมนต์ |
| `REPORT_COMMENT` | มีคนกดแจ้งเนื้อหา |
| `RESOLVE_REPORT` | ปิดรายงานว่า **ซ่อนแล้ว** หรือ **ไม่ดำเนินการ** |
| `MOVE_STUDENTS` | ย้ายนักเรียนเข้าห้องหรือออกจากห้อง |
| `APPLY_ROLLOVER` | กดยืนยันเลื่อนชั้น |

ชื่อเต็มทุกตัวอยู่ใน `audit_logs.action` เปิดดูได้ที่หน้า **บันทึกการใช้งาน** โดยเลือกคอลัมน์ Action

## ปลายทาง API ที่ไม่มีปุ่มบนหน้าจอ

บางงานมีปลายทางให้เรียกแล้ว แต่หน้าจอยังไม่มีปุ่ม ต้องใช้เครื่องมือฝั่งเทคนิคหรือให้ผู้ดูแลระบบทำให้

| ปลายทาง | ทำอะไร | ทำไมไม่มีปุ่ม |
|---|---|---|
| `POST /api/boards/{board_id}/unhide` | เปิดกระทู้ที่ถูกซ่อนคืน | กันการกดผิดบนหน้าจอที่เห็นกันทั่วไป |
| `POST /api/boards/{board_id}/comments/{comment_id}/unhide` | เปิดคอมเมนต์ที่ถูกซ่อนคืน | เหตุผลเดียวกับกระทู้ |
| `PATCH /api/students/{student_id}` | แก้ชื่อ นามสกุล คำนำหน้า เลขที่ รหัสนักเรียน | หน้าจอแก้ได้เฉพาะตำแหน่ง ถ้าจะแก้ชื่อให้ใช้การนำเข้า Excel แทน |

ทุกปลายทางในการเรียกใช้การตรวจสิทธิ์แบบเดียวกับหน้าจอ ถ้าบัญชีไม่มีสิทธิ์จะได้คำตอบ **403** ไม่ใช่ทำงานให้เงียบ ๆ

## ข้อจำกัดและข้อควรระวัง

- ภาคผนวกนี้อ้างโค้ด ณ วันที่เขียน ถ้าโค้ดเปลี่ยนแล้วคู่มือไม่ตาม ให้ยึดพฤติกรรมจริงของระบบ
- ชื่อตารางและฟิลด์ห้ามนำไปใช้เป็นชื่อที่เขียนในคู่มือเล่ม 1 และเล่ม 2 ให้คงคำที่หน้าจอใช้
- การแก้ข้อมูลในฐานข้อมูลตรง ๆ ไม่ผ่าน API จะไม่มีบันทึกการใช้งาน ใช้เป็นทางสุดท้ายเท่านั้น
- ค่าที่มีตัวพิมพ์ใหญ่ทั้งคำ (`PENDING` `APPLIED`) เป็นของงานนำเข้าและงานเลื่อนชั้น ส่วนค่าตัวพิมพ์เล็กเป็นของเรื่อง บอร์ด และกิจกรรม
- อย่าเปลี่ยนรหัสสิทธิ์ใน `roles.json` โดยไม่ตรวจฝั่งหน้าจอ เพราะเมนูผูกกับรหัสตรง ๆ

## ติดปัญหาตรงไหน? ดูวิธีแก้ตรงนี้เลย

**Q: เจอค่าสถานะในฐานข้อมูลที่ไม่ตรงกับที่หน้าจอแสดง?**

👉 **วิธีแก้:** หน้าจอแปลค่าทุกครั้งที่แสดง ให้ดูตาราง **ค่าสถานะในฐานข้อมูล** ในบทนี้ ถ้าไม่ใช่ค่าที่อยู่ในตารางแปลว่ามีโค้ดรุ่นใหม่ที่ยังไม่ได้อัปเดตคู่มือ

**Q: บันทึกการใช้งานมีแถวที่ข้อมูลไม่ได้เปลี่ยนจริง?**

👉 **วิธีแก้:** บันทึกถูกเขียนในธุรกรรมเดียวกับการเปลี่ยน ถ้าเห็นแบบนั้นให้ตรวจว่าแก้ข้อมูลผ่าน API หรือแก้ในฐานข้อมูลตรง ๆ การแก้นอก API จะไม่มีบันทึก จึงเกิดภาพกลับด้านได้

**Q: ลบประกาศแล้วยังเห็นในฐานข้อมูล?**

👉 **วิธีแก้:** ปกติ การลบในระบบนี้แค่ติดเวลาไว้ที่ `deleted_at` แถวยังอยู่ หน้าจอกรองออกให้เอง ถ้าอยากให้หายจากหน้าเว็บแต่ยังเก็บประวัติ ให้ใช้ **ปลดระวาง** แทน

**Q: เปิดกระทู้ที่ถูกซ่อนคืนจากหน้าจอไม่ได้?**

👉 **วิธีแก้:** ปลายทาง `POST /api/boards/{board_id}/unhide` มีให้เรียกแล้วแต่ยังไม่มีปุ่ม ให้ใช้เครื่องมือฝั่งเทคนิคหรือแจ้งผู้ดูแลระบบ

**Q: ครูคนหนึ่งเห็นเมนูไม่ครบทั้งที่ตำแหน่งถูก?**

👉 **วิธีแก้:** ตรวจรหัสสิทธิ์ของตำแหน่งใน `backend/config/roles.json` เทียบกับตาราง **รหัสสิทธิ์** ในบทนี้ และตรวจว่าแถวสมาชิกของคนนั้นอยู่ในปีการศึกษาปัจจุบัน

**Q: `SUPER_ADMIN_ID` ตั้งไว้แล้วทำไมยังไม่มีสิทธิ์?**

👉 **วิธีแก้:** ค่านี้เป็นรหัสผู้ใช้ ไม่ใช่รหัสนักเรียน และตั้งได้ครั้งละหนึ่งคน ถ้าใส่รหัสนักเรียนลงไป ระบบจะไม่เจอผู้ใช้คนนั้นแล้วข้ามค่านี้ไป
