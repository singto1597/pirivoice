# ตั้งค่าระบบ

ค่าที่มีผลกับคนทั้งโรงเรียน ทั้งค่าที่กดได้จากหน้าจอ และค่าที่ต้องแก้ที่ไฟล์แล้ว redeploy
ส่วนใหญ่ไม่ต้องแตะบ่อย แต่ตอนแตะต้องรู้ว่ามันไปกระทบใคร

- 🌙 หน้าจอมีแค่ **ช่วงเวลาไม่ส่งแจ้งเตือน** ที่เหลืออยู่ในไฟล์ตั้งค่า
- 🔁 แก้ `.env` แล้วต้อง redeploy service ที่อ่านค่านั้นถึงจะมีผล
- 🩺 มี `GET /health` ไว้เช็กว่าระบบกับฐานข้อมูลยังคุยกันอยู่

## ใครใช้บทนี้

**ช่วงเวลาไม่ส่งแจ้งเตือน** ใช้สิทธิ์ `MANAGE_SETTINGS` ได้แก่ผู้ดูแลระบบ ครูสภานักเรียน และประธานสภา

ส่วนการแก้ไฟล์ตั้งค่าและหมวดหมู่ ต้องให้ผู้พัฒนาหรือคนที่เข้าถึงเซิร์ฟเวอร์เป็นคนทำ

นักเรียนเปิดดูก่อนได้ว่าโรงเรียนตั้งช่วงเงียบไว้ตอนไหน แก้ไม่ได้

## ก่อนเริ่ม

- การตั้งค่าบางอย่างมีผลทั้งโรงเรียนทันที และไม่มีปุ่มย้อนกลับอัตโนมัติ
- แก้ `.env` ต้อง redeploy service ที่อ่านค่านั้น ก่อนหน้านั้นค่าย่ายังเป็นค่าเดิม
- อย่าเก็บค่าลับ เช่นรหัสฐานข้อมูลหรือคีย์ push ไว้ในเอกสารหรือแชท

## ตั้งช่วงเวลาไม่ส่งแจ้งเตือน

ใช้เมื่อไม่อยากให้มือถือทุกเครื่องเด้งตอนกลางคืนหรือช่วงสอบ

**ทางเข้า:** แท็บ **เพิ่มเติม** ➔ กลุ่ม **บัญชี** ➔ **ตั้งค่า** ➔ การ์ด **ช่วงเวลาไม่ส่งแจ้งเตือน**

1. **เลือกค่าสำเร็จรูป** ข้อใดข้อหนึ่ง — **กลางคืน 22:00–06:00** **ดึก 23:00–05:00** หรือ **ช่วงสอบ 20:00–07:00** ค่าที่เลือกแค่เติมลงช่อง ยังไม่บันทึก
2. **หรือกรอก เริ่ม และ สิ้นสุด** เองในรูปแบบ 24 ชั่วโมง
3. **กด บันทึกช่วงเวลา**
4. **เปิดสวิตช์บนการ์ด** เพื่อให้ช่วงเวลามีผล

สวิตช์บันทึกทันทีที่กด ไม่ต้องกด **บันทึกช่วงเวลา** ซ้ำ
เปิดสำเร็จแล้วจะขึ้น **ระบบจะไม่ส่งแจ้งเตือนถึงมือถือระหว่าง … น. (ข้อความในแอพยังเข้านะ)**

การ์ดบอกสถานะปัจจุบันได้สามแบบ

- ⚪ **ยังไม่ได้ตั้ง — ระบบส่งแจ้งเตือนทุกเวลา** — ยังไม่เคยบันทึกบนการ์ดนี้ ระบบแนะนำ 22:00–06:00 แต่ยังไม่มีผล
- 🌙 **กำลังพักแจ้งเตือนตามช่วงเวลานี้** — สวิตช์เปิดอยู่ ระบบจะพัก push ทุกครั้งที่เวลาปัจจุบันอยู่ในช่วง
- ☀️ **ปิดอยู่ — ส่งแจ้งเตือนทุกเวลา** — เคยบันทึกไว้แล้ว แต่ตอนนี้ปิดสวิตช์

ข้อความ **กำลังพักแจ้งเตือนตามช่วงเวลานี้** บอกแค่ว่าสวิตช์เปิด ไม่ได้บอกว่าตอนนี้อยู่ในช่วงพักหรือเปล่า
ถ้าตั้งช่วงข้ามคืน เช่น 22:00 ถึง 06:00 การ์ดจะต่อท้ายด้วย **(ข้ามคืน)**

นักเรียนเห็นการ์ดนี้แบบอ่านอย่างเดียว พร้อมข้อความ **ค่านี้ตั้งโดยสภานักเรียน — ถ้าต้องการปรับช่วงเวลา กรุณาแจ้งสภานักเรียน**

### ปิดการพักแจ้งเตือนชั่วคราว

กดสวิตช์บนการ์ดให้ปิด ระบบบันทึกทันทีและขึ้น **ปิดการพักแจ้งเตือนแล้ว** พร้อมข้อความ **ระบบกลับมาส่งแจ้งเตือนตามปกติแล้ว**

ช่วงเวลาที่เคยกรอกยังอยู่ครบ เปิดสวิตช์อีกครั้งก็กลับมาใช้ค่าเดิมได้เลย

### ข้อความที่อาจพบ

| ข้อความ | เกิดเมื่อ | ทางแก้ |
|---|---|---|
| **รูปแบบเวลาต้องเป็น HH:MM (เช่น 22:00)** | พิมพ์เวลาไม่ครบหรือใช้ตัวคั่นผิด | พิมพ์แบบ 22:00 |
| **เวลาเริ่มกับเวลาสิ้นสุดต้องไม่เท่ากัน — ถ้าไม่ต้องการปิด push ให้ปิดสวิตช์** | กรอก 22:00 ทั้งสองช่อง | เปลี่ยนเวลา หรือปิดสวิตช์แทน |
| **คุณไม่มีสิทธิ์แก้ไขการตั้งค่าระบบ** | บัญชีไม่มี `MANAGE_SETTINGS` | ให้ผู้ดูแลระบบแก้ให้ |

::: tip ช่วงพักปิดแค่ push ไม่ได้ปิดในแอพ
ข้อความในแอพกับตัวเลขบนไอคอนยังเข้าตามปกติ
ถ้าอยากให้เงียบทั้งแอพระบบยังไม่รองรับ — บอกนักเรียนตรงๆ ว่าเปิดแอพตอนกลางคืนยังเห็นข้อความได้
:::

## เพิ่มหรือแก้หมวดหมู่ของเรื่อง

หมวดหลักมีสามหมวด คือ **เสนอความคิดเห็น** **สุขภาวะทางกายและใจ** และ **แจ้งเหตุ**
หมวดย่อยมีเก้าหมวด และนักเรียนเลือกได้ตอนแจ้งเรื่อง

งานนี้ไม่มีหน้าจอผู้ดูแล ต้องแก้ไฟล์ `backend/config/categories.json` แล้ว redeploy backend
ไม่ต้องแตะฐานข้อมูล

1. **แก้ไฟล์ `backend/config/categories.json`**
2. **เพิ่มหรือแก้คีย์ใน `subcategories` และ `subcategory_details`**
3. **เก็บคีย์เดิมไว้** ถ้าไม่อยากให้เรื่องเก่ากลายเป็นหมวดแปลกปลอม
4. **redeploy backend**
5. **ตรวจหน้าแจ้งเรื่อง** ว่าแสดงหมวดใหม่ครบ และ **ตรวจแดชบอร์ด** ว่าตัวเลขยังรวมได้

เรื่องที่บันทึกด้วยหมวดที่ถูกลบออกจากไฟล์ยังอยู่ครบ แต่แดชบอร์ดจะรวมไว้ใน **อื่นๆ** พร้อมคำอธิบาย **หมวดย่อยที่ไม่อยู่ในระบบปัจจุบัน**
ไม่ใช่ข้อมูลหาย แค่หลุดออกจากการจัดกลุ่มตามหมวดที่กำหนดไว้

## ค่าที่ต้องแก้ผ่านไฟล์ตั้งค่า

ค่าต่อไปนี้อยู่ใน `backend/core/config.py` และอ่านจาก `.env` ที่ root ของโปรเจกต์
เปลี่ยนแล้วต้อง redeploy service ที่เกี่ยวข้อง

| ค่า | ค่าเริ่มต้น | ผลต่อผู้ใช้ |
|---|---|---|
| `ACCESS_TOKEN_EXPIRE_MINUTES` | 43200 | อายุการล็อกอิน 30 วัน |
| `IMPORT_FILE_SIZE_LIMIT_MB` | 10 | ขนาดไฟล์ Excel สูงสุดต่อครั้ง |
| `IMPORT_MAX_ROWS` | 5000 | จำนวนแถวสูงสุดต่อไฟล์ |
| `IMPORT_BATCH_SIZE` | 50 | ขนาดชุดที่ worker เขียนต่อรอบ ไม่กระทบผู้ใช้โดยตรง |
| `IMPORT_RECOVERY_STALE_MINUTES` | 35 | งานนำเข้าที่ค้างเกินนี้ถูกดึงกลับเข้าคิว |
| `QUIET_HOURS` ค่าเริ่มต้นในโค้ด | 22:00–06:00 | ใช้เมื่อยังไม่เคยบันทึกค่าบนหน้าจอ |
| `PUSH_MAX_ATTEMPTS` | 5 | จำนวนครั้งที่ลองส่ง push ก่อนทิ้ง |
| `PUSH_MAX_AGE_MINUTES` | 15 | แจ้งเตือนที่ค้างเกินนี้ไม่ถูกส่ง |
| `PUSH_TICK_SECONDS` | 5 | ความถี่ที่ worker ตรวจคิว push |
| `PUSH_SEND_CONCURRENCY` | 20 | จำนวน push ที่ยิงพร้อมกัน |
| `PUSH_TTL_SECONDS` | 3600 | ระยะที่ปลายทางเก็บข้อความไว้ถ้าเครื่องปิด |
| `PUSH_URGENCY` | high | ระดับความเร่งด่วนของ push |
| `STREAM_HEARTBEAT_SECONDS` | 20 | จังหวะที่เซิร์ฟเวอร์ส่งสัญญาณเลี้ยงการเชื่อมต่อ |
| `STREAM_MAX_SUBSCRIBERS` | 2000 | จำนวนผู้เปิดหน้าเว็บพร้อมกันต่อหนึ่งโปรเซส |

อย่าปรับโดยไม่วัดผล เพราะบางตัวสัมพันธ์กัน
เช่น `PUSH_RECOVER_MINUTES` ต้องน้อยกว่า `PUSH_MAX_AGE_MINUTES` เสมอ ถ้าสลับกัน แจ้งเตือนที่กู้คืนมาจะถูกทิ้งทันที

## ปิดระบบ push ทั้งระบบ

ใช้เมื่อ push สร้างปัญหา เช่น ส่งถี่ผิดปกติ หรือผู้ให้บริการปลายทางล่ม

1. **ลบค่า `VAPID_PUBLIC_KEY` และ `VAPID_PRIVATE_KEY` ออกจาก `.env`**
2. **redeploy worker และ backend**
3. **ตรวจว่าแจ้งเตือนในแอพยังทำงานปกติ**

ปิด push ไม่กระทบข้อความในแอพ และไม่ต้องแก้โค้ด
เปิดกลับมาแล้ว ระบบจะไม่ส่งแจ้งเตือนเก่าที่ค้างอยู่ เพราะมีด่านอายุขัยคัดไว้แล้ว

## ตรวจสุขภาพระบบ

เปิด `GET /health` ที่โดเมนของ backend

- ถ้าฐานข้อมูลเชื่อมต่อได้ จะได้ `{"status": "ok", "database": "connected"}`
- ถ้าไม่ได้ จะได้ `{"status": "error", "database": "disconnected"}`

ไม่ต้องล็อกอิน และไม่เปิดเผยข้อมูลภายใน ใช้เป็นด่านแรกทุกครั้งที่มีคนแจ้งว่าระบบใช้งานไม่ได้

## ระบบทำอะไรเบื้องหลัง

- ช่วงเวลาไม่ส่งแจ้งเตือนเก็บเป็นค่าเดี่ยวในตาราง `app_settings` ภายใต้คีย์ `quiet_hours`
- ยังไม่เคยบันทึก ระบบใช้ค่าเริ่มต้น 22:00–06:00 และถือว่ายังไม่เปิดใช้
- เวลาที่บันทึกตีความเป็นเขตเวลาไทย และครอบข้ามเที่ยงคืนได้ เช่น 22:00 ถึง 06:00
- การอ่านค่าช่วงเวลาเปิดให้ผู้ใช้ที่ล็อกอินทุกคน เพราะนักเรียนต้องรู้ว่าทำไมมือถือเงียบ
- การเขียนต้องมี `MANAGE_SETTINGS` และบันทึกเป็น `UPDATE_QUIET_HOURS` ในทรานแซกชันเดียว
- ช่วงพักมีผลกับ push เท่านั้น ข้อความในแอพและตัวเลขแจ้งเตือนยังเกิดตามปกติ
- ประกาศระดับ **ด่วนมาก** ทะลุช่วงพักได้ เพราะมีธงยกเว้นรายรายการ
- แจ้งเตือนที่ถูกระงับเพราะช่วงพักถูกทำเครื่องหมายว่าจบแล้ว ไม่ได้เก็บไว้ส่งย้อนหลัง
- ถ้าค่าที่บันทึกอ่านไม่ได้ ระบบเลือกหยุดส่ง push ไว้ก่อน ซึ่งปลอดภัยกว่าส่งผิดเวลา

## ข้อจำกัดและข้อควรระวัง

- หน้าจอตั้งค่าได้เฉพาะช่วงเวลาไม่ส่งแจ้งเตือน ค่าอื่นต้องแก้ที่ไฟล์
- ไม่มีหน้าจอแก้หมวดหมู่เรื่อง และไม่มีหน้าจอย้ายเรื่องข้ามหมวด
- เปลี่ยนหมวดหมู่แล้วเรื่องเก่ายังใช้รหัสเดิม ต้องตีความเองในรายงาน
- ไม่มีโหมดปิดปรับปรุง การปิดให้บริการต้องทำที่ proxy หรือหยุด service
- ไม่มีหน้าจอตั้งค่าอีเมล SMS หรือช่องทางอื่น ระบบมีเฉพาะในแอพและ push
- ช่วงพักเป็นค่าทั้งโรงเรียน นักเรียนตั้งเวลาส่วนตัวไม่ได้
- การแก้ `.env` มีผลกับ service ที่ redeploy แล้วเท่านั้น
- เปลี่ยนคีย์ push แล้ว subscription เดิมทั้งหมดใช้ไม่ได้ ผู้ใช้ต้องกดเปิด push ใหม่ทุกคน

## ติดปัญหาตรงไหน? ดูวิธีแก้ตรงนี้เลย

**Q: ตั้งช่วงพักแล้วข้อความในแอพยังเข้าอยู่?**

👉 **วิธีแก้:** ถูกต้องแล้ว ช่วงพักปิดเฉพาะ push ถึงมือถือ ส่วนข้อความในแอพกับตัวเลขบนไอคอนยังทำงาน ถ้าอยากให้เงียบทั้งแอพระบบยังไม่รองรับ

**Q: ตั้งช่วงพักแล้วประกาศด่วนยังเด้ง?**

👉 **วิธีแก้:** ประกาศระดับ **ด่วนมาก** ออกแบบให้ทะลุช่วงพักได้ ถ้าไม่ต้องการพฤติกรรมนี้ ต้องให้ผู้พัฒนาปิดธงยกเว้นของประกาศนั้น

**Q: แจ้งเตือนที่ถูกพักไว้จะส่งย้อนหลังไหม?**

👉 **วิธีแก้:** ไม่ส่ง ระบบทำเครื่องหมายว่าจบแล้วเมื่อพ้นช่วงพัก ผู้ใช้จะเห็นข้อความในแอพแทนตอนเปิดแอพ

**Q: นักเรียนขอปรับช่วงพักเองได้ไหม?**

👉 **วิธีแก้:** ไม่ได้ ค่าเดียวใช้ทั้งโรงเรียน นักเรียนเห็นข้อความให้ติดต่อสภานักเรียน ซึ่งเป็นคนมีสิทธิ์แก้

**Q: เปลี่ยนหมวดหมู่แล้วแดชบอร์ดตัวเลขไม่ตรง?**

👉 **วิธีแก้:** หมวดที่ลบออกจากไฟล์จะถูกนับใน **อื่นๆ** ให้ตรวจว่าเรื่องเก่าที่ใช้หมวดเดิมถูกย้ายหรือยัง หรือเก็บคีย์เดิมไว้ในไฟล์เพื่อให้ยังนับรวม

**Q: แก้ `.env` แล้วค่าไม่เปลี่ยน?**

👉 **วิธีแก้:** ต้อง redeploy service ที่อ่านค่านั้น บางค่าใช้เฉพาะ worker ไม่ใช่ backend ให้ตรวจว่า redeploy ครบทุกตัวที่เกี่ยวข้อง

**Q: `/health` ตอบ error แต่หน้าเว็บยังเปิดได้?**

👉 **วิธีแก้:** หน้าเว็บที่โหลดจากแคชยังแสดงได้ แต่การเรียกข้อมูลจะล้มเหลว ให้ตรวจการเชื่อมต่อฐานข้อมูลและสถานะ service ก่อนแจ้งผู้ใช้
