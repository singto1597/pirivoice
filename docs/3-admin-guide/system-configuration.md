# ตั้งค่าระบบ

บทนี้อธิบายค่าที่ตั้งได้จากหน้าจอ ค่าที่ต้องแก้ผ่านไฟล์ตั้งค่า และผลของแต่ละค่าต่อผู้ใช้
ค่าส่วนใหญ่ไม่มีหน้าจอผู้ดูแล เพราะเปลี่ยนไม่บ่อยและต้อง redeploy

## ใครใช้บทนี้

- การตั้งช่วงเวลาไม่ส่งแจ้งเตือน ใช้สิทธิ์ `MANAGE_SETTINGS` ได้แก่ผู้ดูแลระบบ ครูสภานักเรียน และประธานสภา
- การแก้ไฟล์ตั้งค่าและหมวดหมู่ ต้องให้ผู้พัฒนาหรือผู้ที่เข้าถึงเซิร์ฟเวอร์เป็นผู้ทำ
- ผู้ใช้ทั่วไปอ่านช่วงเวลาไม่ส่งแจ้งเตือนได้ แต่แก้ไม่ได้

## ก่อนเริ่ม

- รู้ว่าการตั้งค่าบางอย่างมีผลทั้งโรงเรียนทันที และย้อนกลับไม่ได้อัตโนมัติ
- การแก้ไฟล์ `.env` ต้อง redeploy service จึงจะมีผล
- ห้ามเก็บค่าลับ เช่นรหัสฐานข้อมูลหรือคีย์ push ไว้ในเอกสารหรือแชท

## ตั้งช่วงเวลาไม่ส่งแจ้งเตือน

ใช้เมื่อไม่ต้องการให้มือถือของทุกคนเด้งตอนกลางคืนหรือช่วงสอบ

1. เปิด **เพิ่มเติม** แล้วเลือก **การตั้งค่า** ที่อยู่ในส่วนโปรไฟล์
2. เลื่อนไปที่การ์ด **ช่วงเวลาไม่ส่งแจ้งเตือน**
3. เลือกค่าสำเร็จรูปข้อใดข้อหนึ่ง คือ **กลางคืน 22:00–06:00** **ดึก 23:00–05:00** หรือ **ช่วงสอบ 20:00–07:00** ค่าที่เลือกจะเติมลงช่องเท่านั้น ยังไม่บันทึก
4. หรือกรอก **เริ่ม** และ **สิ้นสุด** เองในรูปแบบ 24 ชั่วโมง
5. กด **บันทึกช่วงเวลา**
6. กดสวิตช์บนการ์ดให้เปิด เพื่อให้ช่วงเวลามีผล

สวิตช์บันทึกทันทีที่กด ไม่ต้องกด **บันทึกช่วงเวลา** ซ้ำ
หลังเปิดสำเร็จ ระบบขึ้นข้อความว่า **ระบบจะไม่ส่งแจ้งเตือนถึงมือถือระหว่าง … น. (ข้อความในแอพยังเข้านะ)**

การ์ดแสดงสถานะปัจจุบันสามแบบ

| ข้อความ | ความหมาย |
|---|---|
| **ยังไม่ได้ตั้ง — ระบบส่งแจ้งเตือนทุกเวลา** | ยังไม่เคยบันทึกค่าบนการ์ดนี้ ระบบแนะนำ 22:00–06:00 แต่ยังไม่มีผล |
| **กำลังพักแจ้งเตือนตามช่วงเวลานี้** | เปิดสวิตช์ไว้ ระบบจะพัก push ทุกครั้งที่เวลาปัจจุบันอยู่ในช่วง |
| **ปิดอยู่ — ส่งแจ้งเตือนทุกเวลา** | เคยบันทึกไว้แล้ว แต่ปิดสวิตช์อยู่ |

ข้อความ **กำลังพักแจ้งเตือนตามช่วงเวลานี้** บอกว่าสวิตช์เปิดอยู่ ไม่ได้บอกว่าขณะนี้อยู่ในช่วงพักหรือไม่
ถ้าตั้งช่วงข้ามคืน เช่น 22:00 ถึง 06:00 การ์ดจะแสดงคำว่า **(ข้ามคืน)**

นักเรียนเห็นการ์ดนี้แบบอ่านอย่างเดียว พร้อมข้อความ **ค่านี้ตั้งโดยสภานักเรียน — ถ้าต้องการปรับช่วงเวลา กรุณาแจ้งสภานักเรียน**

### ปิดการพักแจ้งเตือนชั่วคราว

1. กดสวิตช์บนการ์ดให้ปิด

ระบบบันทึกทันทีและขึ้น **ปิดการพักแจ้งเตือนแล้ว** พร้อมข้อความ **ระบบกลับมาส่งแจ้งเตือนตามปกติแล้ว**
ค่าช่วงเวลาที่เคยกรอกยังอยู่ และกลับมาใช้ได้เมื่อเปิดสวิตช์อีกครั้ง

### ข้อความที่อาจพบ

| ข้อความ | เกิดเมื่อ | ทางแก้ |
|---|---|---|
| **รูปแบบเวลาต้องเป็น HH:MM (เช่น 22:00)** | พิมพ์เวลาไม่ครบหรือใช้จุดคั่นผิด | พิมพ์เช่น 22:00 |
| **เวลาเริ่มกับเวลาสิ้นสุดต้องไม่เท่ากัน — ถ้าไม่ต้องการปิด push ให้ปิดสวิตช์** | กรอก 22:00 ทั้งสองช่อง | เปลี่ยนเวลา หรือปิดสวิตช์แทน |
| **คุณไม่มีสิทธิ์แก้ไขการตั้งค่าระบบ** | บัญชีไม่มี `MANAGE_SETTINGS` | ให้ผู้ดูแลระบบแก้ |

## เพิ่มหรือแก้หมวดหมู่ของเรื่อง

หมวดหลักมีสามหมวด คือ **เสนอความคิดเห็น** **สุขภาวะทางกายและใจ** และ **แจ้งเหตุ**
หมวดย่อยมีเก้าหมวด และนักเรียนเลือกได้ตอนแจ้งเรื่อง

การเปลี่ยนหมวดหมู่ทำได้โดยแก้ไฟล์ `backend/config/categories.json` แล้ว redeploy backend
ไม่มีหน้าจอผู้ดูแลสำหรับงานนี้ และไม่ต้องแก้ฐานข้อมูล

1. แก้ไฟล์ `backend/config/categories.json`
2. เพิ่มหรือแก้คีย์ใน `subcategories` และ `subcategory_details`
3. รักษาคีย์ของหมวดเดิมไว้ ถ้าไม่ต้องการให้เรื่องเก่ากลายเป็นหมวดแปลกปลอม
4. redeploy backend
5. ตรวจหน้าแจ้งเรื่องว่าแสดงหมวดใหม่ และตรวจแดชบอร์ดว่าตัวเลขยังรวมได้ครบ

เรื่องที่บันทึกด้วยหมวดที่ถูกลบออกจากไฟล์จะยังอยู่ แต่แดชบอร์ดจะรวมไว้ใน **อื่นๆ** พร้อมคำอธิบาย **หมวดย่อยที่ไม่อยู่ในระบบปัจจุบัน**
ไม่ใช่ข้อมูลหาย แต่จะไม่อยู่ในลำดับหมวดหลักที่กำหนด

## ค่าที่ต้องแก้ผ่านไฟล์ตั้งค่า

ค่าต่อไปนี้อยู่ใน `backend/core/config.py` และอ่านจาก `.env` ที่ root ของโปรเจกต์
เปลี่ยนแล้วต้อง redeploy service ที่เกี่ยวข้อง

| ค่า | ค่าเริ่มต้น | ผลต่อผู้ใช้ |
|---|---|---|
| `ACCESS_TOKEN_EXPIRE_MINUTES` | 43200 | อายุการล็อกอิน 30 วัน |
| `IMPORT_FILE_SIZE_LIMIT_MB` | 10 | ขนาดไฟล์ Excel สูงสุดต่อครั้ง |
| `IMPORT_MAX_ROWS` | 5000 | จำนวนแถวสูงสุดต่อไฟล์ |
| `IMPORT_BATCH_SIZE` | 50 | ขนาดชุดที่ worker เขียนต่อรอบ ไม่กระทบผู้ใช้โดยตรง |
| `IMPORT_RECOVERY_STALE_MINUTES` | 35 | งานนำเข้าที่ค้างเกินนี้ถูกดึงกลับเข้าคิว |
| `QUIET_HOURS` ค่าเริ่มต้นในโค้ด | 22:00–06:00 | ใช้เมื่อยังไม่เคยบันทึกค่าบนหน้าจอ |
| `PUSH_MAX_ATTEMPTS` | 5 | จำนวนครั้งที่ลองส่ง push ก่อนทิ้ง |
| `PUSH_MAX_AGE_MINUTES` | 15 | แจ้งเตือนที่ค้างเกินนี้ไม่ถูกส่ง |
| `PUSH_TICK_SECONDS` | 5 | ความถี่ที่ worker ตรวจคิว push |
| `PUSH_SEND_CONCURRENCY` | 20 | จำนวน push ที่ยิงพร้อมกัน |
| `PUSH_TTL_SECONDS` | 3600 | ระยะที่ปลายทางเก็บข้อความไว้ถ้าเครื่องปิด |
| `PUSH_URGENCY` | high | ระดับความเร่งด่วนของ push |
| `STREAM_HEARTBEAT_SECONDS` | 20 | จังหวะที่เซิร์ฟเวอร์ส่งสัญญาณเลี้ยงการเชื่อมต่อ |
| `STREAM_MAX_SUBSCRIBERS` | 2000 | จำนวนผู้เปิดหน้าเว็บพร้อมกันต่อหนึ่งโปรเซส |

ค่าเหล่านี้ไม่ควรปรับโดยไม่วัดผล เพราะบางตัวสัมพันธ์กัน เช่นค่า `PUSH_RECOVER_MINUTES` ต้องน้อยกว่า `PUSH_MAX_AGE_MINUTES` เสมอ
ถ้าปรับสลับกัน แจ้งเตือนที่กู้คืนมาจะถูกทิ้งทันที

## ปิดระบบ push ทั้งระบบ

ใช้เมื่อ push สร้างปัญหา เช่น ส่งถี่ผิดปกติ หรือผู้ให้บริการปลายทางล่ม

1. ลบค่า `VAPID_PUBLIC_KEY` และ `VAPID_PRIVATE_KEY` ออกจาก `.env`
2. redeploy worker และ backend
3. ตรวจว่าแจ้งเตือนในแอพยังทำงานปกติ

การปิด push ไม่กระทบข้อความในแอพ และไม่ต้องแก้โค้ด
เมื่อเปิดกลับ ระบบจะไม่ส่งแจ้งเตือนเก่าที่ค้างอยู่ เพราะมีด่านอายุขัยกันไว้แล้ว

## ตรวจสุขภาพระบบ

เปิด `GET /health` ที่โดเมนของ backend
ถ้าฐานข้อมูลเชื่อมต่อได้ จะได้ `{"status": "ok", "database": "connected"}`
ถ้าไม่ได้ จะได้ `{"status": "error", "database": "disconnected"}`

หน้านี้ไม่ต้องล็อกอิน และไม่แสดงข้อมูลภายใน ใช้เป็นด่านแรกเมื่อมีคนแจ้งว่าระบบใช้งานไม่ได้

## ระบบทำอะไรเบื้องหลัง

- ช่วงเวลาไม่ส่งแจ้งเตือนเก็บเป็นค่าเดี่ยวในตาราง `app_settings` ภายใต้คีย์ `quiet_hours`
- ถ้ายังไม่เคยบันทึก ระบบใช้ค่าเริ่มต้น 22:00–06:00 และถือว่ายังไม่เปิดใช้
- เวลาที่บันทึกตีความเป็นเขตเวลาไทย และครอบข้ามเที่ยงคืนได้ เช่น 22:00 ถึง 06:00
- การอ่านค่าช่วงเวลาเปิดให้ผู้ใช้ที่ล็อกอินทุกคน เพราะนักเรียนต้องรู้ว่าทำไมมือถือเงียบ
- การเขียนค่าต้องมี `MANAGE_SETTINGS` และบันทึกเป็น `UPDATE_QUIET_HOURS` ในทรานแซกชันเดียว
- ช่วงพักมีผลกับ push เท่านั้น ข้อความในแอพและตัวเลขแจ้งเตือนยังเกิดตามปกติ
- ประกาศระดับ **ด่วนมาก** ทะลุช่วงพักได้ เพราะมีธงยกเว้นรายรายการ
- แจ้งเตือนที่ถูกระงับเพราะช่วงพักจะถูกทำเครื่องหมายว่าจบแล้ว ไม่ได้ถูกเก็บไว้ส่งย้อนหลัง
- ถ้าค่าที่บันทึกอ่านไม่ได้ ระบบเลือกหยุดส่ง push ไว้ก่อน ซึ่งปลอดภัยกว่าส่งผิดเวลา

## ข้อจำกัดและข้อควรระวัง

- หน้าจอตั้งค่าได้เฉพาะช่วงเวลาไม่ส่งแจ้งเตือน ค่าอื่นต้องแก้ที่ไฟล์
- ไม่มีหน้าจอแก้หมวดหมู่เรื่อง และไม่มีหน้าจอย้ายเรื่องข้ามหมวด
- เปลี่ยนหมวดหมู่แล้วเรื่องเก่ายังใช้รหัสเดิม ต้องตีความเองในรายงาน
- ไม่มีโหมดปิดปรับปรุงในระบบ การปิดให้บริการต้องทำที่ proxy หรือหยุด service
- ไม่มีหน้าจอตั้งค่าอีเมล SMS หรือช่องทางแจ้งเตือนอื่น ระบบมีเฉพาะในแอพและ push
- ช่วงพักเป็นค่าทั้งโรงเรียน นักเรียนตั้งเวลาส่วนตัวไม่ได้
- การแก้ `.env` มีผลกับ service ที่ redeploy แล้วเท่านั้น
- เปลี่ยนคีย์ push แล้ว subscription เดิมทั้งหมดใช้ไม่ได้ ผู้ใช้ต้องกดเปิด push ใหม่ทุกคน

## แก้ไขปัญหาและคำถามที่พบบ่อย

**ถาม: ตั้งช่วงพักแล้วข้อความในแอพยังเข้าอยู่**
ตอบ: ถูกต้อง ช่วงพักปิดเฉพาะ push ถึงมือถือ ข้อความในแอพและตัวเลขบนไอคอนยังทำงาน
ถ้าต้องการให้เงียบทั้งแอพ ระบบยังไม่รองรับ

**ถาม: ตั้งช่วงพักแล้วประกาศด่วนยังเด้ง**
ตอบ: ประกาศระดับ **ด่วนมาก** ถูกออกแบบให้ทะลุช่วงพักได้
ถ้าไม่ต้องการพฤติกรรมนี้ ต้องให้ผู้พัฒนาปิดธงยกเว้นของประกาศนั้น

**ถาม: แจ้งเตือนที่ถูกพักไว้จะส่งย้อนหลังไหม**
ตอบ: ไม่ส่ง ระบบทำเครื่องหมายว่าจบแล้วเมื่อพ้นช่วงพัก
ผู้ใช้จะเห็นข้อความในแอพแทนเมื่อเปิดแอพ

**ถาม: นักเรียนขอปรับช่วงพักเองได้ไหม**
ตอบ: ไม่ได้ ค่าเดียวใช้ทั้งโรงเรียน
นักเรียนเห็นข้อความให้ติดต่อสภานักเรียน ซึ่งเป็นผู้มีสิทธิ์แก้

**ถาม: เปลี่ยนหมวดหมู่แล้วแดชบอร์ดตัวเลขไม่ตรง**
ตอบ: หมวดที่ลบออกจากไฟล์จะถูกนับใน **อื่นๆ**
ให้ตรวจว่าเรื่องเก่าที่ใช้หมวดเดิมถูกย้ายหรือยัง หรือคงคีย์เดิมไว้ในไฟล์เพื่อให้ยังนับรวม

**ถาม: แก้ `.env` แล้วค่าไม่เปลี่ยน**
ตอบ: ต้อง redeploy service ที่อ่านค่านั้น บางค่าใช้เฉพาะ worker ไม่ใช่ backend
ให้ตรวจว่าแก้แล้ว redeploy ครบทุกตัวที่เกี่ยวข้อง

**ถาม: `/health` ตอบ error แต่หน้าเว็บยังเปิดได้**
ตอบ: หน้าเว็บที่โหลดจากแคชยังแสดงได้ แต่การเรียกข้อมูลจะล้มเหลว
ให้ตรวจการเชื่อมต่อฐานข้อมูลและสถานะ service ก่อนแจ้งผู้ใช้
