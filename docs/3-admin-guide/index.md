# คู่มือผู้ดูแลระบบ

เล่มนี้สำหรับผู้ที่ดูแลโครงสร้างของระบบทั้งหมด ได้แก่ ปีการศึกษา ภาคเรียน ตำแหน่งและสิทธิ์ของสมาชิก
การตั้งค่าที่มีผลทั้งโรงเรียน และการตรวจสอบย้อนหลังเมื่อเกิดปัญหา
ทุกบทเริ่มจากงานที่ต้องทำจริง ไม่ใช่การไล่อธิบายหน้าจอ

## ใครใช้เล่มนี้

| ตำแหน่ง | สิทธิ์พื้นฐาน | งานในเล่มนี้ |
|---|---|---|
| ผู้ดูแลระบบ (`admin`) | `is_admin` | ทำได้ทุกบท |
| ครูสภานักเรียน (`teacher_council`) | `is_admin` | ทำได้ทุกบท |
| ประธานสภา (`council_president`) | `is_admin` | ทำได้ทุกบท |
| ครูทั่วไป (`teacher`) | ไม่มี `is_admin` | เปิดแดชบอร์ดได้เฉพาะระดับชั้นของตน บทอื่นต้องมีสิทธิ์เพิ่ม |

`is_admin` คือแฟล็กที่ทำให้ข้ามการตรวจสิทธิ์รายข้อทั้งหมด
ระบบอ่านค่านี้จากตำแหน่งใน `backend/config/roles.json` ทุกครั้งที่เปลี่ยนตำแหน่ง
จึงไม่มีการตั้ง `is_admin` แยกจากตำแหน่งผ่านหน้าจอ

บัญชีที่กำหนดในตัวแปร `SUPER_ADMIN_ID` ก็ข้ามการตรวจสิทธิ์เช่นกัน
ใช้เมื่อต้องกู้ระบบกรณีไม่มีผู้ดูแลคนใดล็อกอินได้

## สิทธิ์ที่ใช้ในเล่มนี้

| สิทธิ์ | ใช้ทำอะไร | บท |
|---|---|---|
| `MANAGE_STUDENTS` | เพิ่มและแก้สมาชิก กำหนดตำแหน่ง | [จัดการผู้ใช้และตำแหน่ง](user-and-role-management.md) |
| `VIEW_AUDIT_LOG` | เปิดบันทึกการใช้งาน | [ตรวจสอบย้อนหลังด้วยบันทึกการใช้งาน](audit-logs-investigation.md) |
| `MANAGE_SETTINGS` | ตั้งปี ภาคเรียน และช่วงเวลาแจ้งเตือน | [ตั้งค่าปีการศึกษาและภาคเรียน](academic-calendar.md) · [ตั้งค่าระบบ](system-configuration.md) |
| `VIEW_DASHBOARD` | เปิดแดชบอร์ดและสถิติการใช้งาน | [แดชบอร์ดและรายงาน](dashboard-and-reports.md) |

การดูบันทึกการใช้งานต้องมีขอบเขตข้อมูลระดับ `super` หรือ `all` เท่านั้น
ครูทั่วไปแม้ได้สิทธิ์ `VIEW_AUDIT_LOG` ก็ยังถูกปฏิเสธ เพราะเห็นได้เฉพาะระดับชั้น

## เริ่มงานวันแรก

1. เข้าสู่ระบบด้วยบัญชีผู้ดูแลระบบ แล้วเปิด **เพิ่มเติม** เพื่อตรวจเมนูที่เห็น
2. เปิด **ปีการศึกษา** ตรวจว่ามีปีปัจจุบันตรงกับปีที่โรงเรียนใช้อยู่จริง
3. เปิด **ภาคเรียน** ตรวจว่ามีภาคปัจจุบัน และช่วงวันที่ตรงกับปฏิทินโรงเรียน
4. เปิด **สมาชิก** ตรวจว่ามีผู้ดูแลระบบอย่างน้อยหนึ่งคนในปีปัจจุบัน
5. เปิด **ตั้งค่าการแจ้งเตือน** ที่หน้าโปรไฟล์ แล้วกำหนดช่วงเวลาไม่ส่งแจ้งเตือนถ้าต้องการ
6. เปิด **แดชบอร์ด** ตรวจว่าตัวเลขนักเรียนและห้องตรงกับความจริง

| สร้างปีการศึกษา ตั้งปีปัจจุบัน หรือตั้งภาคเรียน | [ตั้งค่าปีการศึกษาและภาคเรียน](academic-calendar.md) |

งานที่เกี่ยวกับข้อมูลนักเรียนรายคน การนำเข้า Excel การเลื่อนชั้น และการมอบหมายเรื่อง
อยู่ใน [คู่มือเจ้าหน้าที่และสภานักเรียน](../2-staff-operations/index.md) ซึ่งผู้ดูแลระบบใช้ได้เช่นกัน

## เมนูของผู้ดูแล

เมนูทั้งหมดอยู่ในแท็บ **เพิ่มเติม**

กลุ่ม **ผู้ดูแล**

- **แดชบอร์ด**
- **จัดการรายงาน**
- **สมาชิก**
- **ย้ายห้องนักเรียน**

กลุ่ม **โรงเรียน**

- **จัดการประกาศ**
- **ปีการศึกษา**
- **เลื่อนชั้นนักเรียน**
- **กระทบยอดรายชื่อ**
- **ภาคเรียน**
- **เรื่องที่ผู้รับหมดวาระ**
- **บันทึกการใช้งาน**

หน้า **เจ้าหน้าที่** และ **นำเข้านักเรียน** ไม่ได้อยู่ในเมนู
เข้าได้จากแท็บและปุ่มในหน้า **สมาชิก**
หน้า **จัดการกิจกรรม** เข้าได้จากแท็บ **จัดการ** ในหน้า **กิจกรรม**

## หลักปฏิบัติเพื่อความปลอดภัย

- ทุกการเพิ่ม แก้ไข และลบข้อมูลสำคัญถูกบันทึกใน **บันทึกการใช้งาน** พร้อมผู้ทำ เวลา และค่าเดิม-ค่าใหม่
- ไม่มีหน้าจอใดให้แก้หรือลบบันทึกการใช้งาน การปกปิดร่องรอยทำได้เฉพาะที่ฐานข้อมูล
- การเปลี่ยนปีปัจจุบันเปลี่ยนค่าเริ่มต้นของปีการศึกษาของสมาชิกใหม่ทันที ต้องทำนอกเวลาใช้งาน
- การลบในระบบนี้เป็นการซ่อน (soft delete) ข้อมูลยังอยู่และกู้คืนได้ ยกเว้นที่ระบุไว้เป็นอย่างอื่น
- เก็บรหัสผ่านและไฟล์สำรองฐานข้อมูลให้พ้นจากเครื่องที่นักเรียนเข้าถึงได้

## งานที่ไม่สามารถย้อนกลับจากหน้าจอ

| งาน | ผลถ้าทำผิด | ทางแก้ |
|---|---|---|
| ยืนยันเลื่อนชั้นทั้งโรงเรียน | สมาชิกทั้งโรงเรียนถูกเขียนใหม่ในครั้งเดียว | กู้จากไฟล์สำรองฐานข้อมูล |
| ปิดเรื่อง | เรื่องปิดแล้วเปิดใหม่จากหน้าจอไม่ได้ | ให้ผู้ดูแลระบบแก้ที่ฐานข้อมูล |
| ลบปีการศึกษาหรือภาคเรียน | ซ่อนจากรายการ แต่กู้คืนได้ | กด **กู้คืน** ในแท็บ **ถูกลบ** |
| เปลี่ยนตำแหน่งสมาชิก | สิทธิ์เปลี่ยนทันที และแถวปีเก่าไม่เปลี่ยนตาม | ตั้งตำแหน่งเดิมคืนให้ถูกปี |

## แก้ไขปัญหาและคำถามที่พบบ่อย

**ถาม: เมนูบางรายการไม่ขึ้นทั้งที่เป็นผู้ดูแลระบบ**
ตอบ: เมนูถูกกรองด้วยสิทธิ์ของบัญชีและยังต้องมีแถวสมาชิกที่ใช้งานในปีปัจจุบัน
ตรวจที่ **สมาชิก** ว่าบัญชีของคุณมีแถวในปีนี้และตำแหน่งยังเป็นผู้ดูแลระบบ

**ถาม: เพิ่มตำแหน่งแล้วสิทธิ์ไม่เปลี่ยนทันที**
ตอบ: ระบบอ่านสิทธิ์จากแถวสมาชิกทุกครั้งที่เรียก API ไม่ได้เก็บไว้ในเบราว์เซอร์
ถ้าหน้าจอยังแสดงเมนูเดิม ให้รีเฟรชหน้าหรือออกแล้วเข้าสู่ระบบใหม่

**ถาม: มีผู้ดูแลระบบได้กี่คน**
ตอบ: ไม่จำกัดจำนวน แต่ต้องมีอย่างน้อยหนึ่งคนในปีปัจจุบันเสมอ
การเลื่อนชั้นจะยกเลิกทั้งงานถ้าปีใหม่ไม่เหลือผู้ดูแลระบบ

**ถาม: ผู้ดูแลระบบรีเซ็ตรหัสผ่านให้นักเรียนได้ไหม**
ตอบ: หน้าจอไม่มีฟังก์ชันนี้ นักเรียนเปลี่ยนรหัสเองที่หน้าโปรไฟล์
ถ้าลืมรหัสจริง ต้องให้ผู้พัฒนาตั้งรหัสใหม่ที่ฐานข้อมูล หรือให้นักเรียนติดต่อผู้ดูแลระบบเพื่อสร้างบัญชีใหม่

**ถาม: ทำไมเห็นข้อมูลนักเรียนไม่ครบทั้งโรงเรียน**
ตอบ: บัญชีอาจมีตำแหน่งที่ผูกกับระดับชั้น เช่นครูทั่วไปหรือประธานระดับ
ผู้ที่เห็นทั้งโรงเรียนคือผู้ดูแลระบบ ครูสภานักเรียน ประธานสภา และตำแหน่งที่มีขอบเขต `all`

**ถาม: ต้องการย้อนดูว่าใครแก้อะไรก่อนเกิดปัญหา ต้องเริ่มที่ไหน**
ตอบ: เปิด **บันทึกการใช้งาน** กรองตามช่วงวันที่และชื่อผู้ใช้
ถ้าไม่รู้ว่าใคร ให้กรองตามชนิดข้อมูลและอ่านค่าเดิม-ค่าใหม่ของรายการที่ใกล้เวลาเกิดเหตุ
